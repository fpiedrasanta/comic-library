# US-0025 — Explorar catálogo de Works

## Objetivo

Permitir al usuario explorar las Works del catálogo desde una única pantalla reutilizable, con búsqueda, filtros estructurales, ordenamiento y scroll infinito.

Esta User Story implementa la entrada general al catálogo:

```text
/catalog
```

La misma experiencia de listado deberá quedar diseñada para ser reutilizada posteriormente desde los contextos de Publisher, Franchise y Series, sin crear implementaciones independientes del listado de Works.

---

## Alcance

La pantalla debe permitir:

* visualizar Works;
* buscar Works;
* filtrar por Publisher, Franchise y Series;
* utilizar la cascada Publisher → Franchise → Series;
* utilizar la cascada inversa mediante selección de Series;
* ordenar los resultados;
* recorrer resultados mediante scroll infinito;
* conservar el estado de navegación en la URL;
* utilizar la pantalla correctamente en Mobile, Tablet y PC.

---

# 1. Ruta

Implementar:

```text
/catalog
```

La pantalla no debe mostrar encabezado contextual.

---

# 2. Resultados iniciales

Al ingresar a `/catalog`, deben mostrarse todos los Works disponibles para el usuario.

Orden inicial obligatorio:

```text
UploadedAt DESC
```

Es decir:

> Las Works subidas más recientemente aparecen primero.

La fecha de subida no representa la fecha de publicación de la obra.

---

# 3. Search

La pantalla debe disponer de un único campo de búsqueda.

La búsqueda debe ser:

* parcial;
* case-insensitive;
* basada inicialmente en `LIKE '%search%'`.

Debe buscar sobre:

```text
Work.Title
Work.Summary
Work.Number.Value
Work.Tags
Person
```

La búsqueda por Person debe encontrar Works relacionadas con la persona independientemente del Role que tenga dentro de la Work.

No implementar búsqueda por múltiples términos independientes.

Ejemplo:

```text
search = spider
```

Debe encontrar coincidencias parciales como:

```text
Spider-Man
Amazing Spider-Man
Spider-Man: Blue
```

---

# 4. Filtros

La pantalla debe disponer únicamente de estos filtros estructurales:

```text
Publisher
Franchise
Series
```

No debe existir un filtro independiente de Tags.

Tags forman parte del Search.

---

# 5. Cascada Publisher → Franchise → Series

Los filtros deben comportarse jerárquicamente.

Al seleccionar un Publisher:

```text
Publisher = Marvel
```

Franchise debe mostrar únicamente franquicias pertenecientes a Marvel.

Al seleccionar una Franchise:

```text
Publisher = Marvel
Franchise = Spider-Man
```

Series debe mostrar únicamente series pertenecientes a Spider-Man.

Cada cambio debe actualizar inmediatamente los Works mostrados.

---

# 6. Cascada inversa

La selección de una entidad inferior debe completar automáticamente sus entidades superiores.

Por ejemplo, al buscar en Series:

```text
Amazing Spider-Man
```

y seleccionar el resultado:

```text
Amazing Spider-Man
Franquicia: Spider-Man
Editorial: Marvel
```

los filtros deben quedar:

```text
Publisher: Marvel
Franchise: Spider-Man
Series: Amazing Spider-Man
```

Los valores superiores se completan automáticamente a partir de la entidad seleccionada.

---

# 7. Reglas de limpieza

Al eliminar Series:

```text
Publisher: Marvel
Franchise: Spider-Man
Series: vacío
```

Publisher y Franchise deben conservarse.

Al eliminar Franchise:

```text
Publisher: Marvel
Franchise: vacío
Series: vacío
```

Series debe limpiarse.

Al eliminar Publisher:

```text
Publisher: vacío
Franchise: vacío
Series: vacío
```

Franchise y Series deben limpiarse.

---

# 8. Autocomplete

Publisher, Franchise y Series deben utilizar autocompletes.

La búsqueda del autocomplete debe utilizar:

```text
LIKE '%search%'
```

y ser case-insensitive.

Escribir texto en un autocomplete no debe aplicar el filtro hasta que el usuario seleccione una entidad.

Los resultados deben poder mostrar contexto secundario cuando corresponda.

Ejemplo:

```text
---------------------------------------
Amazing Spider-Man

Franquicia: Spider-Man
Editorial: Marvel
---------------------------------------
```

---

# 9. Combinación de Search y filtros

Search y filtros deben combinarse.

Conceptualmente:

```text
Publisher
AND Franchise
AND Series
AND Search
```

La ausencia de un filtro no debe restringir los resultados.

---

# 10. Ordenamiento

La pantalla debe permitir:

```text
Ordenar por:
    Título
    Fecha de publicación
    Fecha de subida
    Número
```

y:

```text
Dirección:
    Ascendente
    Descendente
```

Valores iniciales:

```text
Ordenar por: Fecha de subida
Dirección: Descendente
```

---

# 11. Scroll infinito

No implementar:

* paginación tradicional;
* números de página;
* botón "Ver más".

Los resultados deben utilizar **scroll infinito**.

Al cargar más resultados deben mantenerse:

* Search;
* filtros;
* orden;
* dirección;
* contexto de navegación.

---

# 12. Work Card

Implementar una única Work Card reutilizable.

Estructura visual:

```text
┌──────────────────────────────┐
│ [Editorial]                  │
│ [Franquicia]                 │
│ [Serie]                      │
│                              │
│          PORTADA             │
│                              │
│                              │
│                              │
├──────────────────────────────┤
│            NUMBER            │
│ TITLE                        │
│                              │
│ Publicado:       Subido:     │
└──────────────────────────────┘
```

Las pills de Publisher, Franchise y Series deben utilizar el color configurado para cada entidad en la base de datos.

Las pills deben ser navegables hacia sus respectivas entidades.

Si una Work no tiene Number:

* no debe mostrarse Number;
* debe conservarse el espacio visual correspondiente;
* la altura de la card debe mantenerse uniforme.

---

# 13. Navegación desde la Work Card

La Work Card debe permitir navegar hacia la Work correspondiente.

La navegación hacia:

* Publisher;
* Franchise;
* Series;

se realizará mediante sus respectivas pills.

La implementación debe quedar preparada para que las mismas cards sean utilizadas posteriormente en:

```text
/publishers/:id
/franchises/:id
/series/:id
```

---

# 14. URL como estado

El estado de la búsqueda debe reflejarse en la URL.

Deben persistirse los parámetros correspondientes a:

* Search;
* Publisher;
* Franchise;
* Series;
* ordenamiento;
* dirección.

Ejemplo:

```text
/catalog?publisher=2&franchise=8&series=42&search=spiderman&sort=title&direction=asc
```

La URL debe permitir:

* refrescar la página conservando el estado;
* utilizar Back/Forward del navegador;
* compartir una búsqueda;
* recuperar el mismo estado de navegación.

---

# 15. Reutilización

La implementación debe estar preparada para reutilizar la misma página de Works en:

```text
/catalog
/publishers/:id
/franchises/:id
/series/:id
```

No crear componentes o páginas específicas como:

```text
PublisherWorksPage
FranchiseWorksPage
SeriesWorksPage
```

El listado de Works debe implementarse una sola vez.

Los futuros contextos deberán poder proporcionar el contexto inicial:

```text
publisherId?
franchiseId?
seriesId?
```

sin duplicar la experiencia de listado.

---

# 16. Responsive

La pantalla debe funcionar obligatoriamente en:

* Mobile;
* Tablet;
* PC/Desktop.

Debe adaptarse correctamente:

* Search;
* filtros;
* autocompletes;
* ordenamiento;
* Work Cards;
* grilla;
* scroll infinito;
* navegación.

No implementar versiones independientes para cada dispositivo.

---

# 17. Fuera de alcance

Esta User Story no incluye:

* páginas de detalle de Publisher;
* páginas de detalle de Franchise;
* páginas de detalle de Series;
* índices de Publishers;
* índices de Franchises;
* índices de Series;
* lectura de Works;
* reader;
* progreso;
* favoritos;
* guardar para leer después;
* comentarios privados;
* puntuaciones;
* comentarios públicos;
* recomendaciones;
* Lists.

---

# 18. Criterios de aceptación

* [ ] `/catalog` muestra Works ordenadas inicialmente por `UploadedAt DESC`.
* [ ] El usuario puede buscar por Title, Summary, Number.Value, Tags y Person.
* [ ] Search utiliza búsqueda parcial `LIKE '%search%'`.
* [ ] Search es case-insensitive.
* [ ] El usuario puede filtrar por Publisher.
* [ ] El usuario puede filtrar por Franchise.
* [ ] El usuario puede filtrar por Series.
* [ ] Publisher limita las opciones disponibles de Franchise.
* [ ] Franchise limita las opciones disponibles de Series.
* [ ] Seleccionar una Series completa automáticamente Franchise y Publisher.
* [ ] Eliminar Series conserva Publisher y Franchise.
* [ ] Eliminar Franchise limpia Series.
* [ ] Eliminar Publisher limpia Franchise y Series.
* [ ] Escribir en un autocomplete sin seleccionar una entidad no modifica los resultados.
* [ ] Search y filtros se combinan correctamente.
* [ ] El usuario puede ordenar por Título, Fecha de publicación, Fecha de subida y Número.
* [ ] El usuario puede seleccionar dirección Ascendente o Descendente.
* [ ] El orden inicial es Fecha de subida Descendente.
* [ ] Los resultados utilizan scroll infinito.
* [ ] No existe paginación tradicional.
* [ ] Las Works utilizan una única Work Card reutilizable.
* [ ] Las pills utilizan los colores configurados para las entidades.
* [ ] Una Work sin Number mantiene la altura uniforme de la card sin mostrar un placeholder textual.
* [ ] La URL refleja Search, filtros y ordenamiento.
* [ ] Refresh conserva el estado de navegación.
* [ ] Back/Forward permite recuperar estados anteriores.
* [ ] La pantalla funciona correctamente en Mobile.
* [ ] La pantalla funciona correctamente en Tablet.
* [ ] La pantalla funciona correctamente en PC/Desktop.
* [ ] La implementación no crea variantes independientes de la WorksPage para Publisher, Franchise o Series.
