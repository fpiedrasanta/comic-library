# US-0027 — Explorar listas

## Objetivo

Como usuario autenticado, quiero explorar las listas oficiales de obras disponibles en el sistema y consultar el contenido de cada lista, para descubrir y acceder rápidamente a conjuntos de obras organizados por el sistema.

---

# Alcance

La funcionalidad comprende:

1. Listado y exploración de listas.
2. Búsqueda de listas.
3. Filtrado de listas.
4. Consulta del detalle de una lista.
5. Visualización de las obras pertenecientes a una lista en el orden definido por la propia lista.

La funcionalidad estará disponible para usuarios autenticados.

---

# Pantalla 1 — Listado de listas

## Ruta

```text
/lists
```

## Contenido

La pantalla debe mostrar las listas oficiales disponibles.

Cada tarjeta de lista debe mostrar:

* Imagen de portada.
* Tipo de lista.
* Nombre de la lista.
* Cantidad de obras incluidas.

La descripción **no se muestra en la tarjeta**.

La tarjeta completa debe ser clickeable y navegar a:

```text
/lists/{id}
```

## Imagen de portada

La portada de una lista representa una **tapa vertical de comic**, no un logo.

Debe:

* ocupar completamente su área visual;
* utilizar `object-fit: cover`;
* no utilizar padding interno;
* tener bordes redondeados;
* poder utilizar el color distintivo de la lista como acento visual.

No debe asumirse que la imagen original tiene una relación de aspecto determinada.

---

# Búsqueda

La pantalla debe permitir buscar listas mediante un único campo de búsqueda.

La búsqueda debe realizarse sobre:

* Nombre de la lista.
* Descripción de la lista.

La condición es:

```text
Nombre OR Descripción
```

Características:

* búsqueda parcial;
* case-insensitive;
* ejecutada en Backend;
* no requiere coincidencia exacta.

---

# Filtros

La pantalla debe permitir filtrar por:

* Editorial.
* Franquicia.
* Serie.
* Tipo de lista.

## Editorial

Una lista coincide con una editorial cuando contiene al menos una obra perteneciente a esa editorial.

La pertenencia debe respetar la estructura del catálogo:

* obras directamente pertenecientes a la editorial;
* obras pertenecientes a franquicias de esa editorial;
* obras pertenecientes a series de esas franquicias.

## Franquicia

Una lista coincide con una franquicia cuando contiene al menos una obra perteneciente a esa franquicia.

Esto incluye:

* obras directamente pertenecientes a la franquicia;
* obras pertenecientes a series de esa franquicia.

## Serie

Una lista coincide con una serie cuando contiene al menos una obra perteneciente a esa serie.

## Tipo de lista

El filtro debe comparar directamente el `ListTypeId` de la lista.

## Combinación

Los filtros se combinan mediante `AND`.

Ejemplo:

```text
Editorial = Marvel
AND
Franquicia = Spider-Man
AND
Tipo de lista = Cronológica
```

La búsqueda y los filtros también se combinan mediante `AND`.

---

# Autocomplete

Los filtros de:

* Editorial.
* Franquicia.
* Serie.

deben utilizar el mismo comportamiento visual y conceptual utilizado en la exploración del catálogo.

La selección de valores debe ser backend-driven.

Los filtros deben mantener el comportamiento de dependencia utilizado por el catálogo:

```text
Editorial → Franquicia → Serie
```

Las opciones disponibles deben respetar el contexto actualmente seleccionado.

---

# Listado

El listado debe utilizar paginación desde Backend e implementarse visualmente mediante **infinite scroll**.

Debe:

* solicitar páginas sucesivas;
* acumular los resultados;
* evitar duplicados;
* evitar solicitudes concurrentes duplicadas;
* detenerse al alcanzar el final;
* mostrar estados de loading, vacío y error.

Orden inicial:

```text
CreatedAt DESC
```

Es decir, las listas más recientemente creadas aparecen primero.

La API debe permitir ordenar por los criterios soportados por Backend y dirección Ascendente/Descendente.

---

# Pantalla 2 — Detalle de lista

## Ruta

```text
/lists/{id}
```

## Header

Debe mostrar:

* Imagen de portada.
* Tipo de lista.
* Nombre de la lista.
* Descripción/Sinopsis.
* Color distintivo.
* Cantidad de obras.

La descripción se muestra únicamente en esta pantalla, no en la tarjeta del listado.

La portada debe utilizar el mismo tratamiento visual definido para las tarjetas:

* `object-fit: cover`;
* sin padding;
* bordes redondeados;
* formato vertical.

---

# Obras de la lista

Debajo del header deben mostrarse todas las obras pertenecientes a la lista.

Debe utilizarse **el mismo WorkCard existente en el catálogo**.

No crear una variante específica de WorkCard para listas.

Las obras deben mostrarse en el orden definido por la lista mediante `WorkListItem.Position`.

La lista ya define:

* qué obras pertenecen al conjunto;
* en qué orden deben aparecer.

Por lo tanto, esta pantalla **no debe ofrecer**:

* filtros de obras;
* búsqueda de obras;
* ordenamiento de obras.

No debe modificarse el orden definido por la lista desde el cliente.

---

# API

La funcionalidad requiere dos endpoints.

## Listado

```http
GET /api/catalog/lists
```

Debe permitir:

* paginación;
* búsqueda por nombre o descripción;
* filtro por Publisher;
* filtro por Franchise;
* filtro por Series;
* filtro por ListType;
* ordenamiento;
* dirección.

Debe devolver únicamente listas oficiales activas.

Por defecto:

```text
CreatedAt DESC
```

## Detalle

```http
GET /api/catalog/lists/{id}
```

Debe devolver:

* información de la lista;
* tipo de lista;
* descripción;
* portada;
* color;
* cantidad de obras;
* obras incluidas;
* orden de cada obra;
* información necesaria para representar cada WorkCard.

Las obras deben devolverse ordenadas por `WorkListItem.Position`.

---

# Responsive

Las dos pantallas deben funcionar correctamente en:

* Mobile.
* Tablet.
* PC/Desktop.

La distribución visual debe adaptarse al ancho disponible sin perder:

* legibilidad;
* jerarquía visual;
* proporción de las portadas;
* facilidad de navegación.

---

# Componentización

La implementación del Public Web debe estar orientada a componentes.

No debe generarse código duplicado innecesariamente entre:

* listado de listas;
* tarjetas de listas;
* filtros;
* estados de carga;
* estados vacíos;
* errores;
* detalle de lista.

Los componentes reutilizables existentes deben utilizarse cuando correspondan.

---

# UX/UI

Las tareas UX/UI asociadas definen la referencia visual de:

* `/lists`
* `/lists/{id}`

El HTML generado por UX/UI es **únicamente una referencia visual**.

No define el comportamiento funcional.

La funcionalidad real debe respetar esta US y las tareas de implementación correspondientes.

---

# Fuera de alcance

Esta US no incluye:

* creación de listas;
* edición de listas;
* eliminación de listas;
* administración de listas;
* listas creadas por usuarios;
* listas privadas;
* listas colaborativas;
* agregar obras a listas;
* quitar obras de listas;
* reordenar obras de una lista;
* favoritos;
* guardar listas para más tarde;
* recomendaciones;
* comentarios;
* ratings;
* lector de obras;
* progreso de lectura;
* historial de lectura;
* búsqueda o filtrado de obras dentro de una lista.

---

# Criterios de aceptación

* [ ] El usuario autenticado puede acceder a `/lists`.
* [ ] Se muestran únicamente listas oficiales activas.
* [ ] Cada tarjeta muestra portada, tipo, nombre y cantidad de obras.
* [ ] La descripción no aparece en las tarjetas.
* [ ] La búsqueda funciona por nombre o descripción.
* [ ] Se puede filtrar por Editorial.
* [ ] Se puede filtrar por Franquicia.
* [ ] Se puede filtrar por Serie.
* [ ] Se puede filtrar por Tipo de lista.
* [ ] Los filtros se combinan mediante `AND`.
* [ ] El listado utiliza infinite scroll.
* [ ] El orden inicial es `CreatedAt DESC`.
* [ ] La tarjeta navega a `/lists/{id}`.
* [ ] El detalle muestra portada, tipo, nombre, descripción, color y cantidad de obras.
* [ ] El detalle muestra las obras de la lista.
* [ ] Las obras utilizan el WorkCard existente.
* [ ] Las obras respetan exactamente el orden definido por `WorkListItem.Position`.
* [ ] El detalle no permite filtrar, buscar ni ordenar las obras.
* [ ] Las dos pantallas son responsive.
* [ ] La implementación evita duplicación innecesaria mediante componentes reutilizables.
* [ ] Los endpoints requieren autenticación.
* [ ] La API devuelve la información necesaria para representar ambas pantallas.
* [ ] La API no genera consultas N+1 para obtener las listas o sus obras.
