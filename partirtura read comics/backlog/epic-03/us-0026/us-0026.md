# US-0026 — Explorar Publishers, Franchises y Series

## Objetivo

Permitir al usuario explorar las entidades principales del catálogo mediante tres listados:

* Publishers
* Franchises
* Series

Los tres listados comparten el mismo patrón funcional y visual: búsqueda, scroll infinito, cards reutilizables y navegación al detalle de la entidad.

## Rutas

* `/publishers`
* `/franchises`
* `/series`

## Publishers

### Búsqueda

Permitir buscar Publishers por nombre.

La búsqueda debe:

* ser parcial;
* ser case-insensitive;
* ejecutarse contra el backend;
* combinarse con el scroll infinito.

### Card

Cada Publisher se representa mediante una card con:

* imagen/logo;
* nombre.

La imagen debe mantener proporción y utilizar un comportamiento equivalente al utilizado en los headers de Publisher, Franchise y Series:

* contenedor cuadrado;
* imagen con `object-contain`;
* `border-radius`;
* no asumir que el archivo original es perfectamente cuadrado.

### Navegación

Al seleccionar un Publisher:

```text
/publishers/{id}
```

---

## Franchises

### Búsqueda

Permitir buscar Franchises por:

* nombre de Publisher;
* nombre de Franchise.

La búsqueda debe:

* ser parcial;
* ser case-insensitive;
* ejecutarse contra el backend;
* combinarse con el scroll infinito.

### Card

Cada Franchise se representa mediante una card con:

* imagen/logo de la Franchise;
* nombre de la Franchise;
* pill del Publisher asociado, superpuesta sobre el área de imagen.

La pill debe permitir identificar el Publisher asociado.

### Navegación

Al seleccionar una Franchise:

```text
/franchises/{id}
```

---

## Series

### Búsqueda

Permitir buscar Series por:

* nombre de Publisher;
* nombre de Franchise;
* nombre de Series.

La búsqueda debe:

* ser parcial;
* ser case-insensitive;
* ejecutarse contra el backend;
* combinarse con el scroll infinito.

### Card

Cada Series se representa mediante una card con:

* imagen/logo de la Series;
* nombre de la Series;
* pill del Publisher asociado, superpuesta sobre el área de imagen;
* pill de la Franchise asociada, superpuesta sobre el área de imagen.

Las pills deben utilizar la identidad visual/color correspondiente a cada entidad.

### Navegación

Al seleccionar una Series:

```text
/series/{id}
```

---

## Información necesaria

Los contratos utilizados por los listados deben devolver toda la información necesaria para construir las cards y permitir la navegación.

### Publisher

Como mínimo:

```text
Id
Name
Color
UrlImage
```

### Franchise

Como mínimo:

```text
Id
Name
Color
UrlImage

Publisher:
    Id
    Name
    Color
```

### Series

Como mínimo:

```text
Id
Name
Color
UrlImage

Franchise:
    Id
    Name
    Color

Publisher:
    Id
    Name
    Color
```

No debe ser necesario realizar requests adicionales por cada card para obtener esta información.

---

## Scroll infinito

Los tres listados deben utilizar scroll infinito.

No utilizar:

* paginación tradicional visible;
* botón "Load more".

El cliente debe:

* solicitar páginas al backend;
* acumular los resultados;
* evitar resultados duplicados;
* detectar el final del listado;
* evitar requests simultáneos o repetidos innecesariamente.

---

## Componentización

Las tres páginas deben implementarse utilizando componentes reutilizables.

La estructura visual de las cards de Publisher, Franchise y Series debe partir de un mismo componente/base reutilizable, evitando duplicar markup y comportamiento.

Las diferencias entre cards deben resolverse mediante datos y composición, no mediante tres implementaciones independientes.

La misma consideración aplica a:

* búsqueda;
* listado;
* scroll infinito;
* estados de loading;
* estado vacío;
* estado de error.

---

## Responsive

Los tres listados deben funcionar correctamente en:

* Mobile;
* Tablet;
* Desktop.

La distribución de las cards puede adaptarse al viewport, manteniendo una estructura visual consistente.

---

## Fuera de alcance

Esta US no incluye:

* creación o edición de Publishers;
* creación o edición de Franchises;
* creación o edición de Series;
* detalle de las entidades;
* navegación de Works;
* reader;
* progreso de lectura;
* favoritos;
* ratings;
* comentarios;
* recomendaciones;
* listas de usuario.
