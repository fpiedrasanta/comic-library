

# US-0034 — Leer listas del sistema

## Historia de usuario

Como usuario de Comic Library, quiero explorar las listas de Works creadas por el sistema, consultar su contenido y mi progreso de lectura, para descubrir obras relacionadas y continuar leyendo desde la lista.

## Alcance funcional

### 1. Exploración de listas

- Mostrar las listas del sistema disponibles para consulta pública.
- Cada lista debe presentar la información configurada en el sistema, incluyendo nombre, descripción, portada y color cuando corresponda.
- La presentación debe permitir identificar cada lista y acceder a su detalle.
- Las listas inactivas no deben aparecer en Public Web.

### 2. Detalle de una lista

Al seleccionar una lista, mostrar su información y sus Works en el orden definido por el sistema.

El encabezado debe presentar los datos de la lista disponibles: nombre, descripción, portada y color.

Los Works deben mostrarse mediante filas horizontales reutilizables, con la información necesaria para identificarlos y acceder a su detalle o lector.

El orden se determina mediante `WorkListItem.Position`.

En Public Web, las listas del sistema son de solo lectura: no se pueden agregar, quitar ni reordenar Works.

### 3. Progreso de lectura

Para usuarios autenticados, mostrar el progreso de lectura de la lista, calculado a partir de los Works completados por el usuario.

El progreso agregado se calcula como:

`Works completados / Total de Works × 100`

Un Work se considera completado cuando su `WorkReadingProgress.State` es `Completed`.

El progreso debe utilizar los registros existentes de `WorkReadingProgress`, sin crear una entidad de progreso específica para listas.

Para usuarios anónimos, la lista debe seguir siendo consultable, pero no debe mostrar progreso personal ni información privada de lectura.

### 4. Continuar leyendo

La página de detalle debe ofrecer una acción para continuar leyendo cuando corresponda.

Al utilizarla:

1. Si existe un Work de la lista en estado `Reading`, abrir el que tenga la actividad de lectura más reciente.
2. Si no existe ninguno en estado `Reading`, abrir el primer Work incompleto según `WorkListItem.Position`.
3. Si todos los Works están completados, no debe seleccionarse uno como pendiente de lectura.

La navegación debe reutilizar el lector existente. No debe implementar un lector nuevo ni modificar las reglas actuales de progreso.

### 5. Reutilización de componentes

La implementación debe estar preparada para compartir aproximadamente el 90 % de la experiencia con las futuras listas privadas.

Se deben reutilizar, cuando corresponda:

- Página de detalle de lista.
- Encabezado contextual.
- Indicador de progreso.
- Lista de Works en filas horizontales.
- Fila de Work.
- Estados de carga, error y contenido vacío.

Las diferencias entre listas del sistema y privadas deben resolverse mediante el contexto y las capacidades correspondientes, sin duplicar la página ni la presentación de los Works.

La visual de referencia existente para las listas del sistema define la presentación esperada. Su comportamiento funcional debe seguir esta historia de usuario y los contratos del proyecto.

### 6. Estados de interfaz

Contemplar los siguientes estados:

- Carga de listas.
- Listas disponibles.
- Sin listas disponibles.
- Carga del detalle.
- Lista sin Works.
- Error al consultar las listas o su detalle.

Los estados deben ser coherentes con los mecanismos existentes de Public Web.

## Fuera de alcance

- Crear, editar o desactivar listas privadas.
- Agregar, quitar o reordenar Works.
- Favoritos.
- Valoraciones y comentarios de listas.
- Recomendaciones de listas.
- Modificaciones del lector o de las reglas de progreso.
- Administración de listas desde Public Web.

## Criterios de aceptación

- Las listas del sistema activas pueden explorarse desde Public Web.
- Cada lista permite acceder a su detalle.
- El detalle muestra los datos disponibles de la lista y sus Works.
- Los Works se muestran en filas horizontales reutilizables.
- Se respeta el orden definido por `WorkListItem.Position`.
- Public Web no permite modificar la composición ni el orden de las listas del sistema.
- Los usuarios autenticados ven su progreso de lectura, sin afectar el de otros usuarios.
- Los usuarios anónimos pueden consultar las listas sin acceder a información privada.
- La acción de continuar leyendo respeta las reglas de selección establecidas.
- Se reutilizan los componentes existentes siempre que corresponda, evitando duplicar la experiencia que luego utilizarán las listas privadas.
- Se contemplan los estados de carga, error y contenido vacío.
- No se implementan funcionalidades fuera del alcance definido.
