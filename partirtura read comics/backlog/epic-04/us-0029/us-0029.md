# US-0029 — Leer una Work

## Objetivo

Como usuario autenticado, quiero leer una Work dentro de un Reader inmersivo, página por página, para poder recorrer su contenido de forma natural independientemente del formato o proporción de sus páginas.

---

## Alcance

La User Story implementa exclusivamente la experiencia de lectura de una Work.

El Reader debe estar diseñado como un componente reutilizable, de manera que posteriormente pueda utilizarse para otros contextos de lectura, como Lists.

La funcionalidad de persistencia de progreso, historial y estado de lectura se implementará en User Stories posteriores.

---

## Entrada al Reader

Desde `/works/{id}` debe existir una acción **Leer**.

Al seleccionarla:

```text
/works/{id}/read
```

El Reader debe:

* requerir autenticación;
* poder abrirse directamente mediante URL;
* funcionar correctamente mediante refresh;
* respetar navegación Back/Forward del navegador;
* cargar la Work correspondiente;
* mostrar sus páginas en orden.

No se debe ofrecer desde el Reader acceso rápido al catálogo ni al detalle de la Work.

---

## Presentación de páginas

El Reader muestra **una única imagen por vez**.

Cada página debe conservar siempre su relación de aspecto original.

El Reader **NO debe asumir que todas las páginas tienen el mismo tamaño o proporción**.

Debe soportar, entre otros, los siguientes casos:

### Página apaisada

Ejemplo conceptual: páginas con varias viñetas distribuidas horizontalmente, como una página de *Mafalda*.

```text
┌──────────────────────────────────────┐
│ ┌───┐ ┌───┐ ┌───┐ ┌───┐              │
│ │   │ │   │ │   │ │   │              │
│ └───┘ └───┘ └───┘ └───┘              │
│ ┌───┐ ┌───┐ ┌───┐ ┌───┐              │
│ │   │ │   │ │   │ │   │              │
│ └───┘ └───┘ └───┘ └───┘              │
└──────────────────────────────────────┘
```

### Página tradicional

```text
┌───────────────┐
│               │
│               │
│               │
│               │
│               │
│               │
└───────────────┘
```

### Página doble

Una imagen puede representar dos páginas físicas consecutivas:

```text
┌───────────────────────────┐
│                           │
│        PÁGINA DOBLE       │
│                           │
└───────────────────────────┘
```

La imagen debe tratarse como **una única página del Reader** y nunca dividirse automáticamente.

### Reglas

* No recortar páginas para adaptarlas al viewport.
* No deformar imágenes.
* No asumir orientación vertical.
* No asumir orientación horizontal.
* No dividir automáticamente una imagen.
* No alterar la composición original de la página.
* El área disponible para lectura debe adaptarse dinámicamente a la proporción de cada imagen.
* La imagen debe utilizar `object-fit: contain`.
* Debe existir espacio suficiente para que la página sea completamente visible cuando el nivel de zoom lo permita.

---

## Indicador de página

El Reader debe mostrar la posición actual:

```text
Página 12 de 32
```

El indicador debe actualizarse al cambiar de página.

No se debe proporcionar:

* ingreso directo de número de página;
* slider para recorrer páginas;
* thumbnails de páginas.

La experiencia buscada es equivalente a recorrer físicamente un cómic.

---

## Navegación

Debe permitir:

* página siguiente;
* página anterior;
* primera página;
* última página.

La navegación hacia la última página debe respetar la lógica normal de lectura: debe avanzar página por página rápidamente, ejecutando la misma transición de cambio de página y manteniendo el comportamiento del Reader.

No debe realizarse un salto visual directo que evite la secuencia de páginas.

---

## Cambio de página

El cambio de página debe tener una **animación visual de transición**.

La animación es un requisito funcional del Reader y no un detalle opcional de diseño.

Debe transmitir visualmente la sensación de pasar una página física.

La implementación debe:

* ejecutarse al avanzar;
* ejecutarse al retroceder;
* respetar la dirección del movimiento;
* funcionar correctamente en dispositivos táctiles y escritorio;
* no deformar ni recortar la página durante la transición;
* mantener una duración suficientemente breve para no dificultar una lectura rápida.

### Sonido

El cambio de página debe poder reproducir un **sonido de paso de página**.

El sonido forma parte de la experiencia del Reader.

Debe:

* reproducirse al cambiar de página;
* respetar las restricciones de reproducción de audio de los navegadores;
* poder activarse/desactivarse desde la configuración del Reader;
* no reproducirse cuando el usuario tenga el sonido desactivado;
* no bloquear la navegación si el audio no puede reproducirse.

El estado de configuración del sonido será responsabilidad de la implementación del Reader.

---

## Navegación táctil

En dispositivos táctiles:

* swipe hacia la izquierda → página siguiente;
* swipe hacia la derecha → página anterior.

También se debe permitir avanzar o retroceder mediante toque en los laterales de la zona de lectura.

Los gestos no deben interferir con:

* zoom;
* desplazamiento necesario de una página ampliada;
* controles del Reader.

---

## Teclado

En escritorio se debe soportar:

* `ArrowRight` → página siguiente;
* `ArrowLeft` → página anterior;
* `Home` → primera página;
* `End` → última página;
* `+` → zoom in;
* `-` → zoom out.

La implementación no debe interferir con campos de entrada que eventualmente existan dentro de overlays o configuración.

---

## Zoom

El Reader debe permitir ampliar y reducir la página mediante:

* botones `+` / `−`;
* rueda del mouse;
* pinch gesture en dispositivos táctiles.

El zoom debe mantener las proporciones originales de la imagen.

Una página ampliada no debe deformarse.

Cuando una imagen exceda el viewport, debe poder desplazarse para inspeccionar su contenido.

---

## Modo inmersivo

El Reader debe disponer de un modo inmersivo en el que los controles visuales puedan ocultarse.

El usuario debe poder:

* ocultar los controles;
* volver a mostrarlos;
* continuar navegando mientras los controles están ocultos.

La página debe ocupar la mayor cantidad posible del área disponible sin modificar su proporción.

---

## Fullscreen

Debe existir una opción para utilizar el Reader en fullscreen mediante la API correspondiente del navegador.

El fullscreen debe funcionar independientemente del tamaño y orientación de la página.

Debe contemplarse:

* desktop;
* teléfonos;
* tablets;
* orientación portrait;
* orientación landscape.

---

## Overlay / menú del Reader

El Reader debe disponer de un menú superpuesto para las opciones de configuración y control de la experiencia de lectura.

El menú debe poder ocultarse completamente para priorizar la lectura.

Como mínimo deberá contemplar las opciones relacionadas con:

* sonido de cambio de página;
* fullscreen;
* modo inmersivo;
* controles del Reader.

El detalle visual del menú se definirá en la tarea de UX/UI correspondiente.

---

## Adaptación al dispositivo

El Reader debe ser responsive.

La prioridad de diseño es:

1. teléfonos alrededor de 480 px de ancho;
2. tablets;
3. desktop.

Debe funcionar correctamente en:

* portrait;
* landscape;
* diferentes resoluciones;
* diferentes proporciones de pantalla.

La adaptación debe hacerse sobre el área disponible, **no sobre la proporción original de la página**.

---

## Carga de páginas

Las páginas deben solicitarse individualmente.

No se debe descargar el cómic completo como un único recurso.

El Reader debe poder solicitar una página independientemente de las demás.

La carga de una página no debe bloquear innecesariamente la navegación del Reader ni impedir que otras páginas se carguen.

### Precarga

El Reader debe precargar páginas próximas a la posición actual, especialmente las siguientes y anteriores.

La precarga debe respetar el orden de lectura y estar orientada a que, cuando el usuario avance o retroceda, la página correspondiente ya esté disponible o tenga su carga iniciada.

La precarga no debe impedir que el usuario solicite directamente la página que necesita.

---

## Estados de carga

Mientras una página está cargando debe mostrarse un indicador visual de carga.

No se debe mostrar un área vacía sin explicación.

La carga debe ser independiente por página.

---

## Errores de carga

Si una página no puede cargarse, el Reader debe mostrar explícitamente el error.

Debe existir una acción:

```text
Reintentar
```

Un error de carga:

* no debe cerrar el Reader;
* no debe expulsar al usuario de la aplicación;
* no debe producir un estado silencioso;
* no debe impedir continuar cuando sea posible.

---

## Seguridad y acceso

Solamente usuarios autenticados pueden acceder al Reader.

Las páginas deben servirse mediante el mecanismo de protección definido para imágenes privadas/Blob.

No se debe exponer un mecanismo de descarga del cómic completo.

No se implementarán mecanismos específicos para impedir que el usuario guarde una imagen que ya recibió el navegador.

No se utilizarán marcas de agua.

No se ofrecerá:

* descarga CBR;
* descarga CBZ;
* descarga PDF;
* descarga del cómic completo.

---

## Navegación entre Works

La Work puede tener relaciones explícitas `PreviousWork` y `NextWork`.

El Reader debe permitir navegar directamente hacia esas Works cuando corresponda.

La navegación debe llevar directamente al Reader de la Work destino, sin pasar por su pantalla de detalle.

La Work destino deberá abrirse posteriormente según su propio estado de lectura.

La lógica de persistencia del estado será implementada en la User Story correspondiente.

La navegación mediante el orden de una List **no forma parte de esta User Story** y será implementada posteriormente cuando exista el contexto de lectura de Lists.

---

## Reutilización del Reader

La implementación debe realizarse de forma **orientada a componentes**, evitando duplicar lógica o markup.

El Reader debe diseñarse de forma que su núcleo pueda reutilizarse posteriormente para:

* lectura de una Work;
* lectura de una List;
* otros contextos de lectura definidos por el producto.

La implementación actual solamente debe resolver la lectura individual de una Work.

El contexto de lectura debe mantenerse desacoplado de la implementación específica de Work cuando sea razonable hacerlo.

---

## Persistencia de progreso

**Fuera de alcance de esta User Story.**

Esta User Story no implementa:

* `CurrentPage`;
* porcentaje de lectura;
* estado `Reading`;
* estado `Completed`;
* `LastReadAt`;
* historial;
* continuar lectura.

Estos comportamientos serán implementados en User Stories posteriores.

El Reader debe quedar preparado para integrarse con ellos.

---

## Fuera de alcance

No implementar:

* progreso de lectura;
* historial;
* continuar lectura;
* listas como contexto de lectura;
* orden de lectura de Lists;
* Arcos como contexto;
* Crossovers como contexto;
* favoritos;
* ratings;
* reviews;
* comentarios;
* notas sobre páginas;
* anotaciones;
* recomendaciones;
* funcionalidades sociales;
* listas personales;
* thumbnails de páginas;
* búsqueda dentro del Reader;
* filtros;
* ordenamiento;
* administración de Works;
* procesamiento CBR/CBZ;
* funcionalidades de IA;
* descarga del cómic;
* watermark;
* mecanismos anti-`Save image as`;
* acceso rápido al catálogo desde el Reader;
* acceso rápido al detalle de la Work desde el Reader.

---

* [ ] Se muestra una única imagen por vez.
* [ ] Las imágenes conservan siempre su proporción original.
* [ ] Se soportan páginas verticales, horizontales y cuadradas.
* [ ] Una imagen que representa una página doble se trata como una única página.
* [ ] No se recortan ni deforman las páginas.
* [ ] Se muestra el indicador `Página X de Y`.
* [ ] Se puede avanzar y retroceder.
* [ ] Se puede ir a la primera página.
* [ ] Se puede ir a la última mediante avance secuencial.
* [ ] El cambio de página posee una animación visual.
* [ ] Existe sonido de cambio de página.
* [ ] El sonido puede activarse/desactivarse.
* [ ] El Reader funciona con mouse/touch/teclado.
* [ ] Swipe izquierdo avanza.
* [ ] Swipe derecho retrocede.
* [ ] Los toques laterales permiten navegar.
* [ ] Existe zoom mediante botones.
* [ ] Existe zoom mediante rueda del mouse.
* [ ] Existe zoom mediante pinch.
* [ ] El zoom conserva la proporción de la imagen.
* [ ] Una página ampliada puede desplazarse.
* [ ] Los controles pueden ocultarse.
* [ ] Existe modo fullscreen.
* [ ] El Reader funciona en portrait y landscape.
* [ ] El diseño prioriza dispositivos alrededor de 480 px.
* [ ] Las páginas se solicitan individualmente.
* [ ] Las páginas próximas se precargan.
* [ ] La carga de una página no bloquea innecesariamente otras cargas.
