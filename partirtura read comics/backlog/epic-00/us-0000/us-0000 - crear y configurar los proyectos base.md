US-0000 — Crear y configurar los proyectos base

Como equipo de desarrollo, necesitamos disponer de los tres proyectos base correctamente creados y configurados para poder comenzar el desarrollo funcional del sistema.

La User Story comprende la preparación inicial de:

API
Public Web
Dashboard

Cada proyecto debe:

Ser creado utilizando el stack tecnológico definido.
Tener la estructura inicial establecida por su arquitectura.
Tener instaladas las dependencias iniciales necesarias.
Tener configurada la estructura necesaria para comenzar el desarrollo.
Cumplir las coding rules definidas para el proyecto correspondiente.
Estar preparado para ser versionado independientemente.

La configuración realizada debe ser consistente con los documentos de arquitectura y tecnología vigentes.

Criterios de aceptación

La User Story se considera finalizada cuando:

Existe un proyecto independiente para la API.
Existe un proyecto independiente para el Public Web.
Existe un proyecto independiente para el Dashboard.
Cada proyecto posee la estructura inicial definida por su arquitectura.
Cada proyecto utiliza el stack tecnológico definido para él.
Las dependencias iniciales necesarias están instaladas.
La configuración inicial permite comenzar el desarrollo de las funcionalidades del sistema.
Los tres proyectos se encuentran preparados para utilizar control de versiones independiente.
No se incorpora funcionalidad de negocio que pertenezca a otras User Stories.
La estructura resultante permite a los agentes correspondientes comenzar a ejecutar Tasks de desarrollo.
Fuera de alcance

Esta Epic no incluye:

Implementación de funcionalidades de negocio.
Registro de usuarios.
Login.
Gestión de comics.
Lectura de comics.
Gestión de catálogo.
Progreso de lectura.
Calificaciones.
Reseñas.
Recomendaciones.
Cualquier otra funcionalidad funcional del sistema.

Estas funcionalidades serán desarrolladas en Epics posteriores.

Resultado esperado

Al finalizar esta Epic, el sistema debe contar con una base técnica funcional sobre la cual puedan comenzar a ejecutarse las User Stories de producto.

El resultado debe permitir que los agentes de Backend, Frontend Public Web y Frontend Dashboard reciban y ejecuten Tasks de desarrollo sin necesidad de crear nuevamente la estructura fundamental de sus respectivos proyectos.
