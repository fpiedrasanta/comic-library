# US-0009 — Eliminar mi cuenta

## Historia de usuario

**Como** usuario autenticado de Comic Library

**Quiero** poder eliminar mi cuenta de forma segura

**Para** dejar de utilizar la plataforma y eliminar mi acceso personal al sistema.

## Objetivo

Implementar el flujo de baja de la cuenta de un usuario autenticado desde el Public Web.

La eliminación de la cuenta debe requerir una confirmación adicional mediante un código temporal de 6 dígitos enviado al email asociado a la cuenta.

El usuario no debe ingresar nuevamente su email, ya que su identidad se obtiene del contexto de autenticación.

## Descripción

El usuario podrá iniciar el proceso de eliminación desde la sección **"Configuración"** de su cuenta.

El proceso debe:

1. Informar al usuario sobre las consecuencias de eliminar su cuenta.
2. Solicitar el envío de un código temporal de verificación al email asociado a la cuenta.
3. Permitir ingresar el código de 6 dígitos recibido.
4. Validar el código.
5. Si el código es válido, ejecutar la baja de la cuenta.
6. Invalidar las sesiones activas del usuario.
7. Cerrar la sesión actual.
8. Redirigir al usuario fuera del área autenticada.

El frontend no debe enviar el email ni el identificador del usuario para determinar qué cuenta debe eliminarse. El backend debe obtener la identidad del usuario autenticado desde el contexto de autenticación.

## Seguridad

La eliminación de una cuenta no debe poder ejecutarse únicamente mediante una solicitud autenticada.

Debe existir una segunda validación mediante un código temporal enviado al email asociado a la cuenta.

El código debe:

- Tener 6 dígitos.
- Tener una vigencia limitada.
- Ser de un solo uso.
- No poder reutilizarse después de una eliminación exitosa.
- Estar asociado al usuario autenticado que inició la operación.

El backend debe validar que el código corresponde al usuario autenticado que solicita la eliminación.

El email del usuario no debe aceptarse desde el frontend como mecanismo para seleccionar la cuenta.

## Baja de la cuenta

La eliminación de la cuenta debe respetar la regla global de persistencia del sistema:

**Nunca se deben eliminar físicamente registros mediante DELETE.**

La cuenta debe ser dada de baja mediante eliminación lógica utilizando `IsActive = false`.

La baja de la cuenta debe impedir que el usuario vuelva a autenticarse normalmente mientras la cuenta permanezca inactiva.

Los datos relacionados con la cuenta no deben eliminarse físicamente como consecuencia de esta operación.

Las relaciones existentes con la cuenta deberán conservarse de acuerdo con las reglas de integridad y persistencia definidas para cada entidad.

## Sesiones

Una vez confirmada la eliminación de la cuenta:

- La sesión actual debe quedar invalidada.
- Todas las demás sesiones activas del usuario deben quedar invalidadas.
- Los Refresh Tokens asociados a esas sesiones no deben poder utilizarse para obtener nuevos Access Tokens.

La operación debe tener el mismo efecto que un **"Cerrar todas las sesiones"**, pero además debe dejar la cuenta inactiva.

## Resultado esperado

Al finalizar esta User Story:

1. Un usuario autenticado puede iniciar la baja de su cuenta desde Settings.
2. El sistema envía un código de confirmación al email asociado a la cuenta.
3. El usuario puede ingresar el código de 6 dígitos.
4. El sistema valida el código.
5. Una vez validado, la cuenta queda inactiva.
6. Todas las sesiones activas del usuario quedan invalidadas.
7. El usuario deja de poder acceder a las funcionalidades autenticadas.
8. La cuenta no es eliminada físicamente de la base de datos.

## Fuera de alcance

Esta User Story no comprende:

- Administración de cuentas de otros usuarios.
- Reactivación de una cuenta eliminada.
- Eliminación física de datos de la base de datos.
- Eliminación o anonimización de contenido generado por el usuario.
- Eliminación de cómics, obras u otros contenidos del sistema.
- Gestión administrativa de usuarios desde el Dashboard.

Estas funcionalidades deberán definirse, si corresponden, en User Stories posteriores.
