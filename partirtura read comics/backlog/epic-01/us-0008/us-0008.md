# US-0008 — Gestionar sesiones y cerrar sesión

## Historia de usuario

**Como** usuario autenticado de Comic Library

**Quiero** poder cerrar mi sesión actual o cerrar todas las sesiones activas de mi cuenta

**Para** controlar de forma segura dónde permanece abierta mi cuenta y poder revocar el acceso desde otros dispositivos cuando sea necesario.

## Objetivo

Permitir al usuario gestionar las sesiones activas asociadas a su cuenta.

El sistema debe tratar cada inicio de sesión como una sesión independiente. Cerrar una sesión debe afectar únicamente al dispositivo o contexto desde el cual se realizó la operación.

El usuario debe disponer además de una opción para cerrar todas las sesiones activas de su cuenta, permitiendo revocar el acceso desde otros dispositivos en caso de pérdida, robo o sospecha de acceso no autorizado.

## Descripción

Cuando un usuario inicia sesión desde un dispositivo o aplicación, el sistema debe crear una sesión independiente para ese contexto.

Por ejemplo, si un usuario inicia sesión desde una computadora y posteriormente desde un teléfono, ambas sesiones deben permanecer activas de forma independiente.

Si el usuario cierra sesión desde el teléfono:

- La sesión del teléfono debe quedar invalidada.
- La sesión de la computadora debe permanecer activa.

Si el usuario selecciona la opción **"Cerrar todas las sesiones"**, todas las sesiones activas asociadas a su cuenta deben quedar invalidadas.

Esta opción debe estar disponible desde la configuración de la cuenta y debe permitir al usuario revocar el acceso de dispositivos que ya no controla.

## Sesiones independientes

Cada sesión debe poseer su propio mecanismo de renovación de autenticación.

La existencia de múltiples sesiones simultáneas del mismo usuario no debe provocar que una sesión invalide automáticamente a las demás.

Por ejemplo:

```text
Computadora
    └── Sesión A → activa

Teléfono
    └── Sesión B → activa

Tablet
    └── Sesión C → activa
```

Cerrar la sesión B debe producir:

```text
Computadora
    └── Sesión A → activa

Teléfono
    └── Sesión B → cerrada

Tablet
    └── Sesión C → activa
```

Cerrar todas las sesiones debe producir:

```text
Computadora
    └── Sesión A → cerrada

Teléfono
    └── Sesión B → cerrada

Tablet
    └── Sesión C → cerrada
```

## Public Web y Dashboard

El Public Web y el Dashboard administrativo utilizan el mismo sistema de identidad.

Sin embargo, cada inicio de sesión debe representar una sesión independiente.

Por lo tanto:

- Cerrar sesión en el Public Web no debe cerrar automáticamente una sesión independiente del Dashboard.
- Cerrar sesión en el Dashboard no debe cerrar automáticamente una sesión independiente del Public Web.
- Cerrar todas las sesiones debe invalidar ambas y cualquier otra sesión activa del usuario.

El comportamiento debe ser consistente independientemente de cuál de las aplicaciones origine la operación.

## Cerrar sesión actual

El usuario debe poder cerrar la sesión actual desde el menú de usuario.

Al hacerlo:

1. La sesión actual debe quedar invalidada.
2. El Refresh Token asociado a esa sesión debe dejar de ser válido.
3. La información de autenticación correspondiente debe ser eliminada del frontend.
4. El usuario debe ser redirigido al login correspondiente.
5. Las demás sesiones activas del usuario deben permanecer funcionando.

## Cerrar todas las sesiones

Desde la configuración de la cuenta debe existir una acción para **cerrar todas las sesiones**.

La acción debe informar claramente al usuario que:

- Todas las sesiones activas serán cerradas.
- Los demás dispositivos deberán volver a autenticarse.
- La sesión actual también será invalidada.

Una vez confirmada la operación, todas las sesiones activas asociadas al usuario deben quedar invalidadas.

La funcionalidad debe contemplar especialmente el caso en que el usuario haya perdido o ya no tenga acceso a uno de sus dispositivos.

## Seguridad

Las sesiones deben estar asociadas al usuario autenticado correspondiente.

Un usuario no debe poder invalidar sesiones pertenecientes a otra cuenta.

La invalidación de una sesión debe impedir que su Refresh Token pueda utilizarse posteriormente para obtener nuevos Access Tokens.

La opción de cerrar todas las sesiones debe invalidar todas las sesiones activas del usuario y no solamente la sesión desde la cual se ejecutó la operación.

## Alcance

Esta User Story comprende:

- Gestión de sesiones independientes.
- Cierre de la sesión actual.
- Cierre de todas las sesiones.
- Revocación de Refresh Tokens asociados a sesiones.
- Integración con Public Web.
- Integración con Dashboard.
- Protección de rutas luego de la invalidación de una sesión.
- Opción de cerrar todas las sesiones desde Settings.

## Fuera de alcance

Esta User Story no comprende:

- Visualización detallada de dispositivos o sesiones activas.
- Nombre o identificación de cada dispositivo.
- Fecha y hora del último acceso de cada sesión.
- Ubicación geográfica de las sesiones.
- Eliminación de la cuenta.
- Cambio de contraseña.
- Recuperación de contraseña.
- Administración de usuarios desde el Dashboard.

La eliminación de cuenta será definida en una User Story independiente.

## Criterios de aceptación

### Sesiones independientes

- [ ] Un usuario puede mantener sesiones activas simultáneamente en múltiples dispositivos.
- [ ] Cada inicio de sesión genera una sesión independiente.
- [ ] Las sesiones de distintos dispositivos no se invalidan entre sí.

### Cerrar sesión actual

- [ ] El usuario puede cerrar sesión desde el Public Web.
- [ ] El administrador puede cerrar sesión desde el Dashboard.
- [ ] El logout invalida únicamente la sesión actual.
- [ ] El Refresh Token de la sesión actual deja de ser válido.
- [ ] Las demás sesiones del mismo usuario permanecen activas.
- [ ] El frontend elimina el estado de autenticación correspondiente.
- [ ] El usuario es redirigido al login correspondiente.
- [ ] Una sesión cerrada no puede utilizar su Refresh Token para obtener un nuevo Access Token.

### Cerrar todas las sesiones

- [ ] El usuario dispone de una opción para cerrar todas las sesiones desde Settings.
- [ ] La acción requiere confirmación explícita del usuario.
- [ ] Al confirmar, todas las sesiones activas del usuario quedan invalidadas.
- [ ] Los Refresh Tokens asociados a las sesiones quedan inutilizables.
- [ ] La sesión desde la cual se ejecutó la acción también queda invalidada.
- [ ] Los demás dispositivos deben volver a autenticarse.
- [ ] El usuario puede utilizar esta funcionalidad para revocar el acceso de un dispositivo perdido.

### Public Web y Dashboard

- [ ] Una sesión iniciada en Public Web es independiente de una sesión iniciada en Dashboard.
- [ ] Cerrar sesión en Public Web no cierra una sesión independiente del Dashboard.
- [ ] Cerrar sesión en Dashboard no cierra una sesión independiente del Public Web.
- [ ] Cerrar todas las sesiones invalida las sesiones de ambas aplicaciones.
- [ ] El comportamiento es consistente utilizando cualquiera de las aplicaciones.

### Seguridad

- [ ] Un usuario solamente puede gestionar las sesiones asociadas a su propia cuenta.
- [ ] Una sesión invalidada no puede utilizarse para renovar la autenticación.
- [ ] La invalidación de una sesión no permite acceder posteriormente a recursos protegidos.
- [ ] La invalidación de todas las sesiones revoca todos los Refresh Tokens activos asociados al usuario.

## Resultado esperado

Al finalizar esta User Story, Comic Library deberá permitir que un usuario mantenga sesiones independientes en múltiples dispositivos y aplicaciones.

El usuario podrá cerrar únicamente la sesión que está utilizando o, cuando lo necesite, revocar todas las sesiones activas de su cuenta.

Esto permitirá mantener una sesión abierta en un dispositivo mientras se cierra otra y, al mismo tiempo, disponer de un mecanismo para recuperar el control de la cuenta ante la pérdida o compromiso de un dispositivo.
