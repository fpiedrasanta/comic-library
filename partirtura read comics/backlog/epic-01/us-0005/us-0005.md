# US-0005 — Gestión del perfil personal del usuario

## Historia de Usuario

**Como** usuario autenticado de Comic Library  
**Quiero** consultar y modificar la información de mi perfil personal  
**Para** mantener actualizados mis datos dentro de la plataforma.

## Descripción

El usuario autenticado debe poder acceder a su perfil personal desde el menú de usuario disponible en el Index de la aplicación.

La pantalla de perfil debe permitir consultar y modificar únicamente la información personal que corresponda al usuario autenticado, respetando las reglas de negocio y seguridad definidas para la identidad del usuario.

El acceso al perfil debe estar disponible desde la opción **"Editar Perfil"** del menú desplegable del usuario.

El diseño visual de la pantalla ya se encuentra definido mediante un prototipo HTML y deberá utilizarse como referencia para su implementación en el Public Web.

## Alcance

La historia contempla:

- Acceso al perfil desde el menú del usuario.
- Visualización de los datos actuales del usuario.
- Edición de los datos personales permitidos.
- Actualización de avatar.
- Actualización de nombre.
- Actualización de apellido.
- Visualización del correo electrónico asociado a la cuenta.
- Gestión de nacionalidad como dato opcional.
- Validación de los datos antes de guardar los cambios.
- Confirmación visual de una actualización exitosa.
- Manejo de errores de validación y errores provenientes del backend.
- Respeto de las reglas de autorización: un usuario únicamente puede consultar y modificar su propio perfil.

## Reglas de negocio

1. El perfil corresponde exclusivamente al usuario autenticado.
2. El usuario no puede modificar información perteneciente a otro usuario.
3. El correo electrónico identifica la cuenta y no debe modificarse desde esta funcionalidad, salvo que una regla posterior de negocio establezca explícitamente un mecanismo para hacerlo.
4. La nacionalidad es opcional.
5. La nacionalidad debe seleccionarse desde la entidad de países existente; no se debe almacenar como texto libre.
6. Los datos modificados deben validarse antes de ser enviados al backend.
7. El backend debe ser responsable de validar nuevamente las reglas de negocio.
8. El avatar debe respetar las restricciones definidas por la aplicación para imágenes de perfil.
9. La modificación del perfil no debe alterar las credenciales de autenticación.
10. El cambio de contraseña pertenece al flujo de gestión de credenciales y no forma parte de esta historia.
11. Los usuarios registrados mediante Google deben poder gestionar su perfil de la misma manera que los usuarios registrados mediante email y contraseña.
12. No debe existir una lógica de perfil diferente según el método mediante el cual se creó la cuenta.

## Criterios de aceptación

### CA-01 — Acceso al perfil

**Dado** que el usuario está autenticado  
**Cuando** abre el menú de usuario desde el Index  
**Entonces** debe visualizar la opción **"Editar Perfil"**  
**Y** al seleccionarla debe acceder a su pantalla de perfil.

### CA-02 — Visualización de datos

**Dado** que el usuario accede a su perfil  
**Cuando** la información es cargada  
**Entonces** debe visualizar sus datos actuales  
**Y** no debe visualizar datos pertenecientes a otro usuario.

### CA-03 — Edición de datos personales

**Dado** que el usuario está en su perfil  
**Cuando** modifica los datos permitidos  
**Y** confirma la operación  
**Entonces** los cambios deben enviarse al backend  
**Y** deben persistirse correctamente.

### CA-04 — Nacionalidad opcional

**Dado** que el usuario está editando su perfil  
**Cuando** no selecciona una nacionalidad  
**Entonces** debe poder guardar el perfil correctamente.

**Y cuando** selecciona una nacionalidad válida  
**Entonces** esta debe guardarse correctamente.

### CA-05 — Correo electrónico

**Dado** que el usuario está visualizando su perfil  
**Entonces** debe poder visualizar el correo asociado a su cuenta  
**Y** el correo no debe poder modificarse mediante esta funcionalidad.

### CA-06 — Avatar

**Dado** que el usuario está editando su perfil  
**Cuando** selecciona un nuevo avatar válido  
**Entonces** debe poder guardar el nuevo avatar  
**Y** el perfil debe mostrar el avatar actualizado.

### CA-07 — Validación

**Dado** que el usuario modifica información inválida  
**Cuando** intenta guardar los cambios  
**Entonces** debe visualizar los errores correspondientes  
**Y** no debe enviarse una solicitud inválida al backend.

### CA-08 — Confirmación

**Dado** que el usuario modifica correctamente su perfil  
**Cuando** el backend confirma la actualización  
**Entonces** debe visualizar una confirmación de que los cambios fueron guardados.

### CA-09 — Error del backend

**Dado** que ocurre un error durante la actualización  
**Cuando** el backend rechaza la operación  
**Entonces** debe mostrarse un mensaje comprensible para el usuario  
**Y** no deben exponerse detalles técnicos, stack traces ni información sensible.

### CA-10 — Usuarios registrados mediante Google

**Dado** que el usuario fue registrado mediante Google  
**Cuando** accede a su perfil  
**Entonces** debe disponer de las mismas funcionalidades de gestión de perfil que cualquier otro usuario autenticado.

### CA-11 — Seguridad

**Dado** que un usuario está autenticado  
**Cuando** consulta o modifica su perfil  
**Entonces** únicamente debe poder acceder y modificar su propia información.

## Fuera de alcance

No forman parte de esta historia:

- Cambio de contraseña.
- Recuperación de contraseña.
- Cambio de correo electrónico.
- Gestión administrativa de usuarios.
- Eliminación de cuenta.
- Configuración avanzada de la cuenta.
- Gestión de sesiones.
- Gestión de métodos de autenticación externos.
- Administración de países.

Estas funcionalidades podrán ser abordadas mediante historias de usuario independientes.

## Prototipo

El diseño visual de la pantalla de perfil se encuentra definido en los prototipos HTML del proyecto y debe utilizarse como referencia para la implementación.

La navegación hacia esta pantalla parte del **Index autenticado**, cuyo template ya se encuentra disponible.

La opción correspondiente en el menú del usuario es:

**Editar Perfil**

## Dependencias

- Usuario autenticado.
- Sistema de autenticación existente.
- Información del usuario disponible en el backend.
- Entidad de países/nacionalidades existente.
- Index autenticado del Public Web.
- Componentes reutilizables existentes para formularios, validaciones y selección de países, cuando corresponda.

## Resultado esperado

El usuario debe poder ingresar a **Editar Perfil**, visualizar su información personal, modificar los datos permitidos y guardar los cambios de manera segura, independientemente de si su cuenta fue creada mediante registro tradicional o mediante Google.
