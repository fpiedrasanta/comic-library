# US-0012 — Administrar usuarios administradores

## Tipo

User Story funcional.

## Historia de Usuario

**Como** administrador de la plataforma,

**quiero** consultar y gestionar los usuarios que poseen el rol `Administrator`,

**para** poder administrar de forma segura quiénes tienen acceso al Dashboard administrativo.

## Objetivo

Permitir que los administradores autorizados puedan gestionar las cuentas que poseen acceso administrativo al sistema.

La funcionalidad comprende la consulta, creación, modificación y desactivación lógica de usuarios administradores.

La gestión del rol administrativo debe realizarse exclusivamente mediante esta funcionalidad y no debe formar parte de la gestión del perfil personal de un usuario.

## Alcance

El administrador podrá:

- Consultar usuarios administradores.
- Buscar usuarios administradores.
- Ordenar y paginar el listado.
- Consultar el detalle de un usuario administrador.
- Crear un nuevo usuario administrador.
- Modificar la información permitida de un usuario administrador.
- Desactivar lógicamente un usuario administrador.
- Reactivar un usuario administrador previamente desactivado, cuando corresponda.

La funcionalidad deberá permitir distinguir claramente entre usuarios administradores activos e inactivos.

## Datos administrables

La información administrable deberá respetar las reglas generales de identidad del sistema.

Podrán gestionarse, según corresponda:

- Nombre.
- Apellido.
- Email.
- País.
- Avatar.
- Estado de la cuenta.
- Credenciales necesarias para el acceso administrativo.

El rol `Administrator` será asignado por esta funcionalidad y no podrá ser modificado desde la gestión del perfil personal.

## Seguridad

El acceso a esta funcionalidad estará restringido a usuarios autorizados para administrar cuentas administrativas.

Un usuario no podrá elevar sus propios privilegios mediante esta funcionalidad.

La modificación del rol de un usuario público a `Administrator` deberá realizarse únicamente mediante una operación administrativa explícita.

Las credenciales deberán respetar las mismas reglas de seguridad definidas para la identidad del sistema.

Las contraseñas nunca deberán almacenarse en texto plano.

## Baja lógica

La desactivación de un usuario administrador será lógica.

No se deberá eliminar físicamente el usuario de la base de datos.

Un usuario administrador desactivado:

- No podrá iniciar una nueva sesión.
- No deberá poder acceder al Dashboard.
- Deberá conservar su información histórica.
- Podrá ser identificado como inactivo en el listado administrativo.

La reactivación deberá volver a permitir su autenticación, siempre que no exista otra condición que impida el acceso.

## Reglas de negocio

- Un usuario administrador debe poseer el rol `Administrator`.
- Un usuario que no posea dicho rol no debe aparecer en el listado de administradores.
- Los usuarios administradores inactivos no deben poder autenticarse.
- No se debe eliminar físicamente una cuenta administrativa.
- La gestión de usuarios administradores no debe modificar información de otros usuarios que no correspondan al alcance de esta User Story.
- La cuenta utilizada para administrar usuarios administradores debe permanecer protegida contra una pérdida accidental de acceso administrativo.

## Resultado esperado

Un administrador autorizado debe poder administrar las cuentas que tienen acceso al Dashboard administrativo, manteniendo el control sobre quién posee privilegios administrativos sin eliminar físicamente la información de las cuentas.

- [ ] Se puede crear un nuevo usuario administrador.

- [ ] Se puede reactivar un usuario administrador cuando corresponda.
