# US-0007 — Cambiar mi contraseña

## Historia de usuario

**Como** usuario autenticado de Comic Library

**Quiero** cambiar mi contraseña desde mi perfil

**Para** mantener el control y la seguridad de mis credenciales de acceso.

## Objetivo

Permitir que un usuario autenticado pueda establecer una nueva contraseña desde la aplicación sin necesidad de utilizar el flujo de recuperación de contraseña.

El cambio de contraseña debe requerir una validación adicional mediante email.

El usuario debe demostrar que tiene acceso a la dirección de email asociada a su cuenta antes de poder establecer la nueva contraseña.

## Descripción

La funcionalidad estará disponible para usuarios autenticados desde el área de perfil de la aplicación.

El usuario podrá iniciar el proceso de cambio de contraseña desde su perfil.

Al solicitar el cambio, el sistema deberá enviar un código temporal de validación a la dirección de email asociada a la cuenta.

El usuario deberá ingresar el código recibido para continuar.

Una vez validado correctamente el código, el sistema permitirá establecer una nueva contraseña.

La nueva contraseña deberá cumplir las mismas reglas de seguridad utilizadas durante el registro y recuperación de contraseña.

El cambio de contraseña debe reutilizar, cuando resulte conveniente, los mecanismos de seguridad ya implementados para `US-0003 — Recuperar contraseña`, evitando duplicar lógica criptográfica o de validación innecesariamente.

## Seguridad

El cambio de contraseña debe requerir una validación adicional mediante email.

La contraseña nunca debe almacenarse en texto plano.

La nueva contraseña debe ser procesada mediante el mecanismo centralizado de hashing existente.

El código de validación debe:

- Ser temporal.
- Tener una expiración configurable.
- Ser almacenado de forma segura.
- No almacenarse en texto plano.
- No registrarse en logs.
- Ser de un solo uso.

El sistema no debe permitir cambiar la contraseña únicamente por disponer de una sesión autenticada.

Esto evita que una sesión comprometida sea suficiente para cambiar las credenciales permanentes de la cuenta.

## Contraseña

La nueva contraseña debe cumplir las reglas de seguridad existentes:

- Mínimo 8 caracteres.
- Al menos un número.
- Al menos una letra minúscula.
- Al menos una letra mayúscula.
- Al menos un carácter especial.

## Sesiones existentes

Luego de cambiar correctamente la contraseña, las sesiones persistentes existentes deben quedar invalidadas mediante la revocación de los Refresh Tokens activos de la cuenta.

El Access Token actualmente utilizado podrá continuar siendo válido hasta su expiración natural.

Una vez expirado, el usuario deberá autenticarse nuevamente para obtener una nueva sesión.

## Diferencia con recuperar contraseña

Esta funcionalidad no reemplaza `US-0003 — Recuperar contraseña`.

### Cambiar contraseña

- El usuario está autenticado.
- Inicia el proceso desde la aplicación.
- Se utiliza la cuenta actualmente autenticada.
- Se solicita validación adicional mediante email.
- Permite cambiar voluntariamente la contraseña.

### Recuperar contraseña

- El usuario no necesita estar autenticado.
- Se inicia desde la pantalla de recuperación.
- El usuario proporciona su email.
- Se utiliza un código de recuperación enviado por email.
- Permite recuperar el acceso cuando el usuario olvidó su contraseña.

Ambos flujos pueden reutilizar componentes técnicos comunes.

## Resultado esperado

Un usuario autenticado debe poder:

1. Acceder a la opción de cambio de contraseña desde su perfil.
2. Solicitar el cambio.
3. Recibir un código temporal por email.
4. Ingresar y validar el código.
5. Establecer una nueva contraseña.
6. Recibir confirmación de que la contraseña fue modificada.
7. Tener sus Refresh Tokens anteriores revocados.

Si el código es incorrecto, expiró o ya fue utilizado, el sistema debe impedir el cambio de contraseña.

## Fuera de alcance

Esta User Story no comprende:

- Recuperación de contraseña para usuarios que no pueden iniciar sesión.
- Modificación del email.
- Modificación de otros datos del perfil.
- Cambio de rol.
- Gestión administrativa de contraseñas de otros usuarios.
- Autenticación mediante Google.

## Criterios de aceptación

- [ ] Un usuario autenticado puede iniciar el cambio de contraseña desde su perfil.
- [ ] El sistema envía un código de validación a la dirección de email asociada al usuario.
- [ ] El código tiene expiración.
- [ ] El código no se almacena en texto plano.
- [ ] El código no aparece en logs.
- [ ] Un código incorrecto impide continuar.
- [ ] Un código expirado impide continuar.
- [ ] Un código utilizado no puede reutilizarse.
- [ ] El usuario puede establecer una nueva contraseña después de validar correctamente el código.
- [ ] La nueva contraseña cumple las reglas de seguridad existentes.
- [ ] La nueva contraseña se almacena utilizando el password hasher existente.
- [ ] La contraseña anterior deja de ser válida después del cambio.
- [ ] Los Refresh Tokens activos del usuario son revocados después del cambio.
- [ ] El Access Token actualmente utilizado no se modifica como consecuencia directa del cambio.
- [ ] El flujo no requiere conocer la contraseña anterior.
- [ ] El flujo reutiliza los mecanismos técnicos existentes de recuperación de contraseña cuando corresponda.
- [ ] El cambio de contraseña no modifica ningún otro dato del perfil.
