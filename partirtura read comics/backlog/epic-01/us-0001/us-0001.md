# US-0001 — Registrarse

## Historia

Como persona que desea utilizar la aplicación, quiero crear una cuenta mediante mi dirección de email y una contraseña para poder acceder al sistema y utilizar sus funcionalidades personalizadas.

## Descripción

El sistema debe permitir que una persona cree una cuenta proporcionando:

* Nombre.
* Apellido.
* Email.
* Contraseña.
* Nacionalidad.
* Avatar.

La cuenta no debe considerarse registrada de forma efectiva hasta que la dirección de email haya sido validada.

Al completar correctamente el formulario de registro, el sistema debe crear la cuenta en un estado que permita identificar que el email todavía no fue validado y enviar un mecanismo de validación al email indicado.

El usuario debe completar la validación para que la cuenta pueda utilizarse normalmente.

## Email

El email debe:

* Ser obligatorio.
* Tener un formato válido.
* Ser único dentro del sistema.
* Requerir validación antes de activar efectivamente la cuenta.

La validación debe utilizar un mecanismo seguro y con una vigencia limitada.

No se debe considerar validado un email simplemente porque el usuario lo haya informado durante el registro.

## Contraseña

La contraseña debe ser obligatoria y cumplir las reglas de contraseña fuerte definidas para el sistema.

La contraseña nunca debe almacenarse en texto plano.

Debe almacenarse utilizando el mecanismo seguro de hashing definido por el stack tecnológico.

Las reglas concretas de complejidad deben estar centralizadas y no implementarse de manera aislada en cada pantalla o endpoint.

## Nacionalidad

La nacionalidad es un dato obligatorio del usuario.

No debe almacenarse como un `string` libre.

Debe utilizar la representación de dominio definida para la nacionalidad, permitiendo identificar de manera consistente la nacionalidad seleccionada.

## Avatar

El avatar debe poder ser asociado al usuario durante el registro.

La implementación debe respetar las reglas de almacenamiento y procesamiento de archivos definidas para el sistema.

El usuario no debe poder utilizar una URL arbitraria como mecanismo para asociar un avatar si esto contradice las reglas de seguridad definidas para el sistema.

## Resultado esperado

Cuando el registro es válido:

1. Se crea el usuario.
2. El usuario queda identificado como no validado.
3. Se envía el mecanismo de validación al email informado.
4. El usuario no puede utilizar funcionalidades que requieran una cuenta validada hasta completar la validación.
5. Una vez validado el email, la cuenta queda habilitada para iniciar sesión.

Si el registro no es válido, el sistema debe informar el motivo correspondiente sin exponer información sensible.

## Criterios de aceptación

### Registro válido

* Se puede registrar un usuario proporcionando todos los datos obligatorios.
* El email queda registrado como no validado.
* Se genera y envía el mecanismo de validación.
* La contraseña se almacena de forma segura.
* La nacionalidad queda asociada mediante su representación de dominio.
* El usuario queda correctamente asociado con su avatar cuando corresponde.

### Validación del email

* El usuario puede validar su email utilizando el mecanismo recibido.
* Un mecanismo de validación expirado no puede utilizarse.
* Un mecanismo de validación ya utilizado no puede reutilizarse.
* Después de una validación exitosa, el usuario queda identificado como validado.
* Una cuenta cuyo email no fue validado no puede utilizar funcionalidades que requieran una cuenta validada.

### Datos inválidos

El sistema debe rechazar el registro cuando:

* Falta un dato obligatorio.
* El email tiene un formato inválido.
* El email ya se encuentra registrado.
* La contraseña no cumple las reglas de seguridad.
* La nacionalidad no corresponde a una nacionalidad válida del sistema.
* Los datos del avatar no cumplen las reglas establecidas.

### Seguridad

* La contraseña nunca se almacena en texto plano.
* Los mecanismos de validación no deben permitir la activación de cuentas sin demostrar el acceso al email registrado.
* La información sensible no debe exponerse en las respuestas de la API.

## Fuera de alcance

Esta User Story no incluye:

* Inicio de sesión.
* Registro mediante Google.
* Recuperación de contraseña.
* Cambio de contraseña.
* Administración de usuarios.
* Gestión posterior del perfil.
