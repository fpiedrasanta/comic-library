# US-0023 — Administrar listas de obras

## Objetivo

Permitir la administración de listas de obras (`WorkList`) utilizadas para organizar y presentar conjuntos ordenados de obras.

Las listas serán creadas inicialmente por el sistema/administrador. El modelo debe quedar preparado desde el inicio para soportar posteriormente listas creadas por usuarios, tanto privadas como públicas.

## Actor

Administrator.

## Modelo

### WorkList

* `Id`
* `Name`
* `Description`
* `Cover`
* `Color`
* `ListTypeId`
* `OwnerType`

  * `System`
  * `User`
* `OwnerUserId`

  * `null` para listas `System`
  * obligatorio para listas `User`
* `Visibility`

  * `Private`
  * `Public`
* `IsActive`
* `CreatedAt`

### WorkListItem

* `WorkListId`
* `WorkId`
* `Position`

`Position` determina el orden de lectura/presentación de las obras dentro de la lista.

## Reglas

* Una `WorkList` pertenece a un `OwnerType`.
* `OwnerType = System` implica `OwnerUserId = null`.
* `OwnerType = User` implica `OwnerUserId` obligatorio.
* El administrador puede crear y administrar listas `System`.
* El formulario administrativo no permite modificar `OwnerType`.
* Las listas `System` son públicas inicialmente.
* `Visibility` debe existir en el modelo aunque actualmente las listas `System` se creen como públicas.
* Una lista utiliza un único `ListType`.
* Un `ListType` inactivo no puede seleccionarse al crear o modificar una lista.
* Una lista puede contener múltiples obras.
* Una obra puede pertenecer a múltiples listas.
* Una obra no puede aparecer más de una vez dentro de la misma lista.
* Cada obra debe tener una única `Position` dentro de una lista.
* El orden de las obras puede modificarse.
* Eliminar una obra de una lista no elimina la obra del catálogo.
* Eliminar una lista no elimina ninguna obra.
* La eliminación de listas será lógica mediante `IsActive`.
* No realizar eliminación física.

## Funcionalidad

### Listado de listas

Permitir:

* Listar listas paginadas.
* Buscar por nombre.
* Filtrar por estado.
* Ordenar.
* Crear una lista.
* Editar una lista.
* Desactivar una lista.
* Reactivar una lista.

### Formulario de lista

Permitir configurar:

* Portada.
* Color.
* Nombre.
* Tipo de lista.
* Descripción.

El selector de Tipo de Lista debe utilizar los `ListType` activos.

Debe existir acceso a la administración de Tipos de Lista desde el formulario, siguiendo el patrón utilizado en otras relaciones administrables del Dashboard cuando corresponda.

### Obras de la lista

Permitir:

* Agregar obras a la lista.
* Buscar y filtrar obras utilizando los mecanismos existentes del catálogo.
* Mostrar las obras actualmente agregadas.
* Eliminar obras de la lista.
* Reordenar las obras mediante drag & drop.
* Persistir el nuevo orden.

La selección de obras debe reutilizar los componentes y mecanismos existentes para búsqueda/listado de `Work` siempre que sea posible.

## Alcance inicial

La administración corresponde a listas `System`.

El modelo debe quedar preparado para futuras listas `User`, pero esta US no implementa:

* Creación de listas por usuarios.
* Listas privadas de usuarios.
* Compartir listas.
* Administración de listas de otros usuarios.
* Permisos avanzados.
* Listas colaborativas.

## Fuera de alcance

* Modificación o eliminación de obras del catálogo desde una lista.
* Administración avanzada de `ListType`.
* Jerarquías entre listas.
* Listas dentro de listas.
* Estadísticas de listas.
* Comentarios.
* Likes/favoritos de listas.
* Compartición entre usuarios.
* Colaboración sobre listas.

## Criterios de aceptación

* El administrador puede crear una lista `System`.
* El administrador puede editar sus datos.
* El administrador puede seleccionar únicamente `ListType` activos.
* El administrador puede agregar obras.
* Una obra no puede agregarse dos veces a la misma lista.
* El administrador puede eliminar obras de la lista sin afectar el catálogo.
* El administrador puede modificar el orden de las obras.
* El orden queda persistido mediante `Position`.
* El administrador puede desactivar y reactivar listas.
* Desactivar una lista no elimina sus obras ni modifica sus relaciones.
* La estructura soporta `OwnerType = System/User`.
* `OwnerUserId` permanece `null` para las listas `System`.
* `Visibility` queda preparada para el futuro.
* Se respetan las convenciones arquitectónicas y de código existentes.
