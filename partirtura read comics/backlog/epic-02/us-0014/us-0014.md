# US-0014 — Administrar editoriales

## Tipo

User Story funcional.

## Objetivo

Permitir que un administrador gestione las editoriales que forman parte del catálogo de Comic Library.

Una editorial representa la empresa responsable de la publicación de una o más obras disponibles en el sistema.

Además de funcionar como referencia dentro del catálogo, una editorial posee información propia que permitirá posteriormente construir una experiencia pública específica para cada editorial.

## Actor

Administrador.

## Precondiciones

- El usuario debe estar autenticado.
- El usuario debe poseer el rol `Administrator`.

## Alcance

El administrador debe poder:

- Consultar las editoriales existentes.
- Buscar editoriales.
- Ordenar el listado.
- Filtrar por estado.
- Paginar el listado.
- Crear una editorial.
- Modificar una editorial.
- Activar una editorial.
- Desactivar una editorial.

La administración de editoriales pertenece exclusivamente al Dashboard administrativo.

Los usuarios públicos no pueden crear, modificar, activar ni desactivar editoriales.

## Información de una editorial

Una editorial debe poder contener como mínimo:

- Identificador.
- Nombre.
- Descripción.
- Historia.
- Sitio web.
- País.
- Año de fundación.
- Estado de existencia de la editorial.
- Imagen representativa.
- Color.
- Indicador de editorial destacada.
- Estado de actividad.

El identificador es generado y administrado por el sistema.

## Nombre

El nombre de la editorial es obligatorio.

El nombre debe ser único dentro del catálogo.

La unicidad del nombre no depende del estado de actividad.

Una editorial desactivada continúa reservando su nombre y no permite crear otra editorial con el mismo nombre.

## Descripción

La editorial puede tener una descripción.

La descripción permite proporcionar información general sobre la editorial y será utilizada posteriormente como parte de la experiencia pública de la editorial.

La descripción es opcional.

## Historia

La editorial puede tener una historia.

La historia permite al administrador incorporar información histórica y contextual sobre la editorial.

La historia es opcional.

El contenido de la historia es administrado manualmente por el administrador.

La generación automática de contenido mediante inteligencia artificial no forma parte de esta User Story.

## Sitio web

La editorial puede tener un sitio web oficial.

El sitio web es opcional.

Cuando se proporcione, debe cumplir las reglas de validación definidas para una dirección web válida.

## País

La editorial puede tener asociado un país.

El país es opcional.

La representación concreta de esta relación será definida en la especificación técnica correspondiente.

## Año de fundación

La editorial puede tener registrado un año de fundación.

El año de fundación es opcional.

Cuando se proporcione, debe cumplir las reglas de validación correspondientes a un año válido.

## Estado de existencia

La editorial debe poder indicar si continúa existiendo.

El dato se representa mediante `IsAlive`.

Este valor es independiente de `IsActive`.

Por ejemplo, una editorial puede:

- Continuar existiendo y estar activa en el catálogo.
- Haber dejado de existir y continuar activa en el catálogo.
- Haber dejado de existir y estar inactiva en el catálogo.

`IsAlive` representa información sobre la existencia de la editorial y no controla su disponibilidad dentro del sistema.

## Imagen representativa

Una editorial puede tener una única imagen representativa.

La imagen es opcional.

La imagen no está limitada exclusivamente a un logotipo. Puede ser cualquier imagen representativa de la editorial que resulte adecuada para utilizar posteriormente como elemento visual de su página pública.

La imagen debe estar optimizada para utilización web y almacenarse en formato WebP.

El administrador debe poder:

- Cargar una imagen.
- Reemplazar la imagen existente.
- Eliminar la imagen.

La carga de la imagen se realizará desde el Dashboard mediante una interfaz de arrastrar y soltar.

Una editorial no puede tener simultáneamente más de una imagen representativa.

La gestión técnica del almacenamiento y procesamiento de imágenes será definida en la especificación correspondiente.

## Color

Una editorial puede tener asociado un color.

El color es opcional.

El valor persistido debe almacenarse como color hexadecimal.

Ejemplo:

```text
#ED1C24
```

El administrador debe poder seleccionar visualmente el color mediante un componente de selección de color.

El componente podrá ofrecer tanto selección libre como una paleta de colores predefinidos, pero el valor finalmente persistido será hexadecimal.

Si una editorial no tiene color configurado, las interfaces que utilicen el color de la editorial deberán utilizar el color predefinido correspondiente definido por el frontend.

La ausencia de color no impide que la editorial pueda ser utilizada normalmente dentro del catálogo.

El color configurado pertenece a la editorial y podrá ser utilizado posteriormente por las experiencias de catálogo y presentación pública.

## Editorial destacada

Una editorial debe disponer de un indicador `IsFeatured`.

El indicador permite identificar explícitamente aquellas editoriales que el administrador considera destacadas.

El indicador es independiente del color.

Una editorial puede tener color configurado y no estar marcada como destacada.

Una editorial puede estar marcada como destacada independientemente de que tenga o no color configurado.

`IsFeatured` no determina si el color de la editorial debe utilizarse.

La finalidad de `IsFeatured` es permitir posteriormente consultas, filtros o experiencias específicas para editoriales destacadas.

## Consulta de editoriales

El administrador debe poder consultar un listado paginado de editoriales.

El listado debe permitir:

- Buscar por nombre.
- Ordenar por nombre.
- Ordenar por estado de actividad.
- Filtrar por estado de actividad.
- Filtrar por editorial destacada.
- Cambiar la dirección del ordenamiento.
- Navegar entre páginas.

La búsqueda debe permitir localizar una editorial mediante coincidencia parcial de su nombre.

Los criterios concretos de paginación podrán ser definidos durante la especificación técnica.

## Creación

El administrador debe poder crear una nueva editorial.

Como mínimo debe poder proporcionar:

- Nombre.
- Descripción.
- Historia.
- Sitio web.
- País.
- Año de fundación.
- Estado de existencia.
- Imagen representativa.
- Color.
- Indicador de editorial destacada.

Al crear una editorial:

- El nombre es obligatorio.
- El nombre debe ser único.
- La editorial comienza activa.
- El identificador es generado por el sistema.
- El administrador no puede establecer manualmente el identificador.
- La información opcional puede omitirse.

El estado `IsActive` no forma parte del contrato de creación.

Una nueva editorial debe comenzar con `IsActive = true`.

## Edición

El administrador debe poder modificar los datos de una editorial existente.

La edición puede modificar:

- Nombre.
- Descripción.
- Historia.
- Sitio web.
- País.
- Año de fundación.
- Estado de existencia.
- Imagen representativa.
- Color.
- Indicador de editorial destacada.

La edición no puede modificar:

- Identificador.
- Estado de actividad mediante el formulario de edición.

El estado de actividad se administra exclusivamente mediante las operaciones de activación y desactivación.

La edición de una editorial no debe alterar las relaciones existentes de la editorial con otras entidades del catálogo.

## Gestión de imagen durante la edición

El administrador debe poder reemplazar o eliminar la imagen representativa existente.

Al reemplazar una imagen:

- La editorial continúa teniendo una única imagen.
- La imagen anterior deja de ser la imagen vigente de la editorial.

Al eliminar una imagen:

- La editorial permanece disponible.
- No se elimina la editorial.
- El campo de imagen queda sin valor.

## Activación

El administrador debe poder activar una editorial previamente desactivada.

La activación debe:

- Mantener el mismo identificador.
- Mantener todos sus datos.
- Cambiar únicamente el estado de actividad.

La operación debe ser idempotente.

Activar una editorial que ya se encuentra activa no debe generar una segunda entidad ni modificar innecesariamente sus datos.

## Desactivación

El administrador debe poder desactivar una editorial.

La desactivación debe ser lógica.

No debe eliminarse físicamente la editorial.

La desactivación debe:

- Mantener el identificador.
- Mantener todos sus datos.
- Mantener las relaciones existentes.
- Cambiar únicamente el estado de actividad.

Una editorial desactivada no debe estar disponible para nuevas asociaciones que requieran una editorial activa.

Las obras existentes que ya referencien la editorial deben conservar correctamente dicha referencia.

La desactivación no debe modificar ni eliminar automáticamente las obras asociadas.

La operación debe ser idempotente.

Desactivar una editorial que ya se encuentra inactiva no debe generar un error por el mero hecho de encontrarse en ese estado.

## Integridad

El sistema debe garantizar la unicidad global del nombre de la editorial.

La unicidad debe mantenerse independientemente de:

- `IsActive`.
- `IsFeatured`.
- `IsAlive`.

La desactivación de una editorial no libera su nombre.

## Relaciones con otras entidades

Una editorial puede ser referenciada por múltiples obras del catálogo.

La relación con una editorial no debe duplicar la información de la editorial dentro de la obra.

La desactivación de una editorial no debe eliminar ni modificar automáticamente:

- Números.
- Novelas gráficas.
- Series.
- Otras relaciones de catálogo existentes.

Las reglas concretas de asociación de obras con editoriales serán definidas en las User Stories correspondientes.

## Eliminación física

Esta User Story no contempla eliminación física de editoriales.

No debe existir una operación funcional de `DELETE` para una editorial.

La baja funcional de una editorial se realiza mediante desactivación lógica.

## Seguridad

Todas las operaciones de administración de editoriales deben estar protegidas mediante autenticación y autorización de administrador.

El backend debe determinar la identidad y los permisos del usuario.

El cliente no puede modificar el identificador mediante contratos destinados a creación o edición.

El estado `IsActive` no puede modificarse mediante el contrato de creación ni mediante el formulario de edición.

No debe existir ninguna operación pública que permita modificar editoriales.

## Reglas de negocio

1. Una editorial debe tener nombre.
2. El nombre debe ser único globalmente.
3. La unicidad del nombre no depende de `IsActive`.
4. Una nueva editorial comienza activa.
5. La desactivación es lógica.
6. La activación es lógica.
7. La desactivación no elimina relaciones existentes.
8. Una editorial inactiva no debe estar disponible para nuevas asociaciones que requieran una editorial activa.
9. Las obras existentes conservan sus referencias a editoriales desactivadas.
10. El identificador de una editorial no puede modificarse.
11. El estado de actividad no forma parte de la creación ni de la edición.
12. No existe eliminación física de editoriales.
13. Una editorial puede tener como máximo una imagen representativa.
14. La imagen representativa es opcional.
15. La imagen representativa debe estar optimizada para web y almacenarse como WebP.
16. El color es opcional.
17. El color persistido se almacena como hexadecimal.
18. La ausencia de color permite utilizar un color predefinido por el frontend.
19. `IsFeatured` es independiente de `Color`.
20. `IsFeatured` no determina si el color debe mostrarse.
21. `IsAlive` representa la existencia de la editorial y es independiente de `IsActive`.
22. La información histórica de una editorial puede ser administrada manualmente por el administrador.

## Estados

Una editorial tiene dos dimensiones de estado independientes.

### Estado de actividad

#### Activa

La editorial está disponible para ser utilizada en nuevas asociaciones del catálogo.

#### Inactiva

La editorial permanece almacenada y conserva sus relaciones existentes, pero no está disponible para nuevas asociaciones que requieran una editorial activa.

### Estado de existencia

`IsAlive` indica si la editorial continúa existiendo como entidad empresarial/editorial.

Este dato no determina si la editorial puede ser utilizada dentro del catálogo.

## Dependencias

Esta User Story depende de:

- EPIC-01 — Gestión de usuarios e identidad, para autenticación y autorización administrativa.

Las entidades que referencien editoriales dependerán de la existencia de esta capacidad.

## Resultado esperado

El catálogo debe disponer de una administración completa de editoriales.

Cada editorial puede mantener información descriptiva, histórica y visual propia, incluyendo una imagen representativa y un color configurable.

El administrador debe poder mantener esta información sin romper las referencias existentes de las obras.

Una editorial puede dejar de estar disponible para nuevas asociaciones mediante desactivación lógica sin desaparecer del catálogo ni perder sus relaciones históricas.

La información almacenada debe permitir posteriormente construir una experiencia pública diferenciada para cada editorial.
