# US-0017 — Administrar números

## Tipo

User Story funcional.

## Objetivo

Permitir que el administrador consulte, cree, modifique y desactive números pertenecientes a una Serie, administrando su información editorial, continuidad, personas y roles, etiquetas y contenido digital.

Un Número representa una unidad individual de publicación y lectura dentro de una Serie.

El Número hereda su contexto editorial y narrativo de la Serie a la que pertenece.

## Actor

Administrador.

## Precondiciones

- El usuario debe estar autenticado.
- El usuario debe poseer el rol `Administrator`.
- Para crear un Número debe existir una Serie activa.
- La Serie determina la Franquicia y Editorial del Número.
- El Idioma seleccionado debe existir y estar disponible.
- Las Personas y Roles utilizados deben existir, salvo que sean creados mediante los modales correspondientes.
- Las Etiquetas seleccionadas o creadas deben ser válidas.

## Alcance

La User Story comprende:

- Listado administrativo de números de una Serie.
- Creación de números.
- Edición de números.
- Desactivación de números.
- Reactivación de números.
- Administración de portada.
- Administración de descripción.
- Administración de idioma.
- Administración de fecha de publicación.
- Administración de continuidad.
- Administración de personas y roles.
- Administración de etiquetas.
- Carga de archivos CBR.
- Eliminación del contenido digital.
- Visualización del estado de procesamiento.
- Consulta del detalle de errores de procesamiento.
- Reintento del procesamiento.
- Asistencia de IA para descripción.
- Asistencia de IA para sugerencia de etiquetas.

No comprende la administración manual de páginas individuales.

---

# 1. Identidad del Número

Cada Número debe contener como mínimo:

- `Number`
- `Title`
- `Description`
- `Cover`
- `LanguageId`
- `IsActive`
- `PublicationDate`
- `CreatedAt`
- Número anterior.
- Número siguiente.
- Personas y roles.
- Etiquetas.
- Estado del contenido digital.

## 1.1 Number

El campo `Number`:

- Es obligatorio.
- Es de tipo texto.
- Es libre.
- No debe estar restringido inicialmente a determinados prefijos o formatos.
- Puede utilizar valores como:

```text
#REGULAR-0001
#REGULAR-0002
#ANUAL-0001
#APRILFOOL-0001
```

La aplicación no debe asumir inicialmente una estructura concreta del valor.

El formato podrá ser normalizado posteriormente desde la interfaz sin modificar la naturaleza del dato.

No puede existir más de un Número con el mismo `Number` dentro de una misma Serie.

El mismo valor de `Number` puede existir en diferentes Series.

Por ejemplo:

```text
Serie A → #REGULAR-0001
Serie B → #REGULAR-0001
```

es válido.

## 1.2 Title

El título del Número:

- Es obligatorio.
- Es texto libre.
- Puede repetirse en diferentes números.
- Debe poder modificarse posteriormente.

## 1.3 Description

La descripción:

- Es opcional.
- Es texto libre.
- Puede ser modificada manualmente por el administrador.
- Puede ser generada o propuesta mediante asistencia de IA.

La IA no debe guardar automáticamente la descripción sin intervención del administrador.

El administrador puede editar la descripción propuesta antes de guardar.

## 1.4 Cover

El Número puede tener una portada propia.

La portada:

- Es opcional.
- Es independiente de la imagen de la Serie.
- Debe utilizar el mismo patrón de imágenes privadas utilizado por Editoriales, Franquicias y Series.
- Se administra como portada, no como avatar.

Debe ser posible:

- Crear un Número sin portada.
- Agregar una portada.
- Reemplazar una portada.
- Eliminar una portada.
- Conservar una portada existente durante una edición.

La imagen debe enviarse utilizando el patrón establecido para las demás entidades del catálogo.

---

# 2. Serie, Franquicia y Editorial

Un Número pertenece obligatoriamente a una Serie.

La relación es:

```text
Editorial
    |
    └── Franquicia
            |
            └── Serie
                    |
                    └── Número
```

El Número no almacena `FranchiseId`.

El Número tampoco almacena `PublisherId`.

La Editorial y la Franquicia se obtienen a través de la Serie.

## 2.1 Contexto del Número

Al administrar un Número, el administrador debe poder visualizar:

```text
Editorial
Franquicia
Serie
```

Esta información es únicamente informativa.

No debe poder modificarse desde el formulario del Número.

## 2.2 Cambio de Serie

No existe la operación "Cambiar Serie".

Si un Número fue creado dentro de una Serie incorrecta, el flujo previsto es:

```text
Eliminar Número
        ↓
Crear Número en la Serie correcta
```

Las reglas concretas de eliminación se definirán en la especificación correspondiente si fueran necesarias.

---

# 3. Idioma

Cada Número debe tener exactamente un idioma.

El idioma es obligatorio.

El administrador debe poder seleccionar el idioma entre los idiomas disponibles en el catálogo.

El Número no debe almacenar información duplicada del idioma.

Debe referenciar al registro correspondiente mediante `LanguageId`.

---

# 4. Estado del Número

El Número posee un estado administrativo:

`IsActive`.

Los estados posibles son:

```text
Activo
Inactivo
```

El estado:

- Puede modificarse desde las acciones administrativas.
- No forma parte de la carga del contenido digital.
- Es independiente del estado de procesamiento del CBR.

Un Número puede estar:

```text
Activo + sin contenido digital
Activo + procesando
Activo + contenido procesado correctamente
Activo + error de procesamiento
Inactivo + sin contenido digital
Inactivo + procesando
Inactivo + contenido procesado correctamente
Inactivo + error de procesamiento
```

Desactivar un Número no debe interrumpir un procesamiento que se encuentre en curso.

---

# 5. Fecha de publicación

Cada Número debe tener una fecha de publicación.

La fecha:

- Es obligatoria.
- Representa una fecha de calendario.
- No requiere hora.
- Debe visualizarse como `dd/MM/yyyy`.
- Puede utilizarse para búsqueda, filtrado y ordenamiento.

No debe almacenarse como fecha y hora de publicación.

---

# 6. Fecha de subida

El sistema debe registrar automáticamente la fecha y hora en que el Número fue creado/importado.

Este dato corresponde a `CreatedAt`.

El administrador:

- Puede visualizarlo.
- No puede modificarlo.

Debe visualizarse como:

```text
dd/MM/yyyy HH:mm
```

---

# 7. Continuidad

Un Número puede tener:

- Un número anterior.
- Un número siguiente.

Ambos son opcionales.

No todos los números necesitan formar parte de una continuidad completa.

Son válidos, por ejemplo:

```text
Número 20
Anterior: 19
Siguiente: vacío
```

o:

```text
Número 21
Anterior: 20
Siguiente: 22
```

## 7.1 Relaciones explícitas

La continuidad no debe inferirse automáticamente a partir del valor de `Number`.

El administrador debe establecer explícitamente las relaciones.

Por ejemplo:

```text
#REGULAR-0020 → siguiente → #REGULAR-0021
```

debe generar:

```text
#REGULAR-0020 → siguiente → #REGULAR-0021

#REGULAR-0021 → anterior → #REGULAR-0020
```

## 7.2 Actualización bidireccional

Cuando el administrador modifica una relación de continuidad, el sistema debe actualizar automáticamente la relación inversa.

Por ejemplo, si se establece:

```text
Número 21
Anterior = Número 20
```

el sistema debe establecer:

```text
Número 20
Siguiente = Número 21
```

Del mismo modo, si se establece:

```text
Número 20
Siguiente = Número 21
```

el sistema debe establecer:

```text
Número 21
Anterior = Número 20
```

## 7.3 Eliminación o reemplazo de relaciones

Si una relación deja de existir, la relación inversa correspondiente debe limpiarse automáticamente.

El sistema debe evitar relaciones inversas inconsistentes.

Las relaciones de continuidad no deben modificar los datos propios de los números.

---

# 8. Personas y Roles

Un Número puede tener múltiples Personas.

Cada participación debe asociar:

```text
Persona + Rol
```

La relación debe permitir:

- Una Persona con múltiples Roles dentro del mismo Número.
- Un Rol con múltiples Personas dentro del mismo Número.
- La misma Persona en diferentes Roles.
- Diferentes Personas con el mismo Rol.

Ejemplo:

```text
Jhon Doe       Entintador
Juan Salvo     Escritor
Jhon Doe       Dibujante
```

Esto debe representarse mediante una relación conceptual `PersonByRole`.

## 8.1 Selección

El formulario debe permitir seleccionar:

```text
[ Buscar persona... ▼ ] [+]
[ Buscar rol....... ▼ ] [+]
[ Agregar ]
```

El componente de selección debe utilizar un comportamiento equivalente al componente `CountrySearchSelect`.

## 8.2 Agregar participación

Al seleccionar una Persona y un Rol y presionar `Agregar`, la relación debe incorporarse a una lista visible en el formulario.

Ejemplo:

```text
Jhon Doe       Entintador       [x]
Juan Salvo     Escritor         [x]
Jhon Doe       Dibujante        [x]
```

El administrador puede eliminar individualmente una relación.

## 8.3 Crear Persona

El botón `[+]` asociado a Persona debe abrir un modal para crear una nueva Persona.

La Persona:

- Se crea inmediatamente en backend.
- Debe ser validada por el backend.
- No debe duplicarse según las reglas definidas para Persona.
- Una vez creada, debe quedar disponible para selección.
- Debe quedar seleccionada en el formulario actual al cerrar el modal.

## 8.4 Crear Rol

El botón `[+]` asociado a Rol debe abrir un modal para crear un nuevo Rol.

El Rol:

- Se crea inmediatamente en backend.
- Debe ser validado por el backend.
- No debe duplicarse según las reglas definidas para Rol.
- Una vez creado, debe quedar disponible para selección.
- Debe quedar seleccionado en el formulario actual al cerrar el modal.

## 8.5 Guardado parcial

La creación de Personas y Roles desde el formulario no implica guardar el Número.

Esto permite que el administrador pueda crear una Persona o Rol cuando lo necesita y continuar posteriormente con la carga del Número.

El formulario del Número no debe perder su información por abrir estos modales.

---

# 9. Etiquetas

Un Número puede tener múltiples Etiquetas.

Las etiquetas permiten clasificar temática o narrativamente la obra.

## 9.1 Selección

El administrador puede seleccionar etiquetas existentes.

El componente debe permitir:

```text
Etiquetas:
[ acción × ] [ multiverso × ]
```

## 9.2 Creación mediante texto

El administrador también puede escribir una etiqueta.

Por ejemplo:

```text
Escribir: [ terror                         ]
```

Al presionar `Enter`, la etiqueta se incorpora a la selección.

Al guardar el Número:

- Si la etiqueta ya existe, debe utilizarse la existente.
- Si no existe, debe crearse.
- No deben generarse etiquetas duplicadas.

## 9.3 Asistencia de IA

La interfaz debe permitir solicitar sugerencias de etiquetas a la IA.

Ejemplo:

```text
Sugeridas por IA:

[ terror ] [ multiverso ] [ viajes temporales ]
```

Al seleccionar una sugerencia, esta pasa a formar parte de las etiquetas del Número.

Las sugerencias de IA no se consideran definitivas.

El administrador debe decidir cuáles utilizar.

Las etiquetas sugeridas pueden ser:

- Existentes.
- Nuevas.

La creación definitiva de las nuevas etiquetas puede realizarse al confirmar/guardar el Número.

La IA no debe crear automáticamente etiquetas sin confirmación del administrador.

---

# 10. Asistencia de IA para descripción

El formulario debe proporcionar una acción:

```text
[ ✨ Generar con IA ]
```

La IA debe utilizar la información disponible del Número y su contexto para proponer una descripción.

La información disponible puede incluir, entre otros:

- Serie.
- Número.
- Título.
- Editorial.
- Franquicia.
- Personas y roles.
- Etiquetas.
- Otra información editorial disponible.

La descripción generada debe reemplazar el contenido actual del campo.

El administrador puede editarla posteriormente antes de guardar.

La IA no debe persistir automáticamente el resultado.

---

# 11. Contenido digital

Un Número puede tener un archivo digital en formato CBR.

El archivo CBR representa el contenido digital de la obra y debe ser procesado por el backend.

El archivo original no debe conservarse una vez completado el procesamiento.

La lectura posterior debe utilizar las páginas procesadas individualmente.

---

# 12. Carga de CBR

El administrador debe poder cargar un archivo CBR desde el formulario del Número.

El procesamiento debe ejecutarse de forma asíncrona.

El administrador no debe tener que permanecer esperando la finalización del procesamiento.

El estado debe actualizarse independientemente de la edición de metadata del Número.

## 12.1 Estados de contenido

El Número debe tener uno de los siguientes estados de contenido:

```text
Sin archivo
Procesando
Finalizado OK
Error
```

Estos estados representan el estado del contenido digital y son independientes de `IsActive`.

## 12.2 Procesando

Cuando el archivo se encuentre procesándose:

- El Número puede seguir siendo editado.
- El Número puede ser desactivado.
- El Número puede permanecer activo.
- El procesamiento no debe interrumpirse por cambiar `IsActive`.
- El administrador debe poder visualizar que el procesamiento está en curso.

---

# 13. Error de procesamiento

Si el procesamiento falla, el Número debe quedar en estado:

```text
Error
```

El administrador debe poder:

- Consultar el detalle del error.
- Solicitar nuevamente el procesamiento.

La interfaz debe proporcionar acciones equivalentes a:

```text
[Detalle] [Volver a procesar]
```

El error debe poder identificarse claramente desde el formulario y desde el listado.

---

# 14. Eliminación del contenido digital

El administrador debe poder eliminar el contenido digital de un Número.

El flujo previsto es:

```text
Eliminar contenido digital
        ↓
Sin archivo
        ↓
Cargar nuevo CBR
        ↓
Procesando
        ↓
Finalizado OK
```

No existe una acción específica de "Reemplazar CBR".

La eliminación y posterior carga de un nuevo archivo son operaciones independientes.

Eliminar el contenido digital:

- No elimina el Número.
- No desactiva el Número.
- No modifica la Serie.
- No modifica la continuidad.
- No modifica las Personas.
- No modifica las Etiquetas.
- No elimina la metadata del Número.

---

# 15. Disponibilidad para lectura

El estado `IsActive` y el estado del contenido digital son independientes.

Un Número puede estar activo aunque todavía no tenga contenido digital.

En la Public Web, un Número activo sin contenido procesado no debe estar disponible para lectura.

La interfaz pública podrá posteriormente representar estos casos como:

```text
Próximamente
```

o una representación equivalente.

Esta decisión de presentación pública queda fuera del alcance de esta User Story.

---

# 16. Páginas

Las páginas resultantes del procesamiento CBR no son administradas manualmente.

El procesamiento debe:

```text
CBR
 ↓
Validación
 ↓
Descompresión
 ↓
Extracción
 ↓
Conversión a WebP
 ↓
Almacenamiento individual
 ↓
Registro de páginas
```

El administrador no debe crear, eliminar, ordenar ni modificar páginas individualmente desde el Dashboard.

---

# 17. Listado de Números

El listado de Números se accede desde la Serie mediante la acción:

```text
Gestionar números
```

La acción debe estar disponible tanto si la Serie está activa como si está inactiva.

Esto permite cargar números mientras una Serie todavía está desactivada.

## 17.1 Contexto superior

El listado debe mostrar información informativa de:

```text
Editorial
Franquicia
Serie
```

Esta información no debe ser editable desde esta pantalla.

## 17.2 Búsqueda

El listado debe permitir búsqueda por:

- Número.
- Título.

## 17.3 Filtros

Debe permitir filtrar por:

```text
Activas: [ Todas | Sí | No ]

Idioma: [                    ▼ ]

Fecha publicación desde: [            ]
Fecha publicación hasta: [            ]

Estado contenido:
[ Todos | Error | Faltante | Procesando | OK ]
```

`Faltante` representa números que no poseen contenido digital disponible.

## 17.4 Ordenamiento

Debe permitir ordenar por:

- Número.
- Título.
- Fecha de publicación.
- Fecha de subida.
- Idioma.

La dirección debe permitir:

```text
ASC
DESC
```

## 17.5 Orden natural del Número

El ordenamiento por Número debe respetar el formato libre utilizado por el catálogo.

La interfaz debe permitir posteriormente aplicar reglas de orden natural.

Inicialmente los valores pueden seguir convenciones como:

```text
#ANUAL-0001
#ANUAL-0002

#REGULAR-0001
#REGULAR-0002
```

Por lo tanto, cuando corresponda, los números `ANUAL` deben poder aparecer agrupados antes que los `REGULAR`.

No se debe asumir que estos son los únicos prefijos existentes.

## 17.6 Columnas

El listado debe mostrar:

```text
Imagen thumb
Activo
Número
Título
Fecha subida
Fecha publicación
Anterior
Siguiente
Estado contenido
Acciones
```

La portada debe mostrarse como imagen protegida.

## 17.7 Acciones

Para cada Número:

Si está activo:

```text
Editar
Desactivar
```

Si está inactivo:

```text
Editar
Reactivar
```

Las operaciones de activar/desactivar deben utilizar confirmación y mantener el patrón utilizado por Franquicias y Series.

---

# 18. Acceso desde Serie

Desde el listado de Series, cada Serie debe disponer de:

```text
Editar
Gestionar números
Desactivar / Reactivar
```

`Gestionar números` debe estar disponible independientemente del estado de la Serie.

El flujo es:

```text
Series
   ↓
Gestionar números
   ↓
Listado de números de la Serie
```

La Serie seleccionada determina el contexto del listado.

---

# 19. Creación de un Número

El administrador debe poder crear un Número desde el listado de números mediante:

```text
[Agregar Número]
```

La Serie ya se encuentra determinada por el contexto.

El formulario debe mostrar como información:

```text
Editorial
Franquicia
Serie
```

Estos valores no pueden modificarse.

El administrador debe completar como mínimo:

- Número.
- Título.
- Fecha de publicación.
- Idioma.

Opcionalmente puede completar:

- Descripción.
- Portada.
- Continuidad.
- Personas y roles.
- Etiquetas.
- Contenido digital.

---

# 20. Edición de un Número

El administrador debe poder editar un Número existente.

La edición debe cargar todos los datos actuales del Número.

Debe poder modificar:

- Número.
- Título.
- Descripción.
- Portada.
- Idioma.
- Fecha de publicación.
- Continuidad.
- Personas y roles.
- Etiquetas.
- Contenido digital.

`IsActive` no se modifica desde el formulario de edición.

La activación y desactivación se realizan mediante las acciones del listado.

La Serie, Franquicia y Editorial son contexto fijo y no pueden modificarse.

---

# 21. Persistencia y operaciones independientes

La edición de metadata y el procesamiento del contenido digital deben considerarse responsabilidades independientes.

El administrador puede:

- Editar metadata mientras el CBR está procesándose.
- Desactivar el Número mientras se procesa.
- Reactivar el Número mientras se procesa.
- Consultar el estado del procesamiento.
- Continuar trabajando con la metadata aunque el procesamiento falle.

Un error del procesamiento digital no debe invalidar la metadata previamente guardada.

---

# 22. Integridad

El sistema debe garantizar como mínimo:

- Un Número debe pertenecer a una Serie existente.
- El `Number` debe ser único dentro de su Serie.
- El título debe existir.
- El idioma debe existir.
- Las Personas deben existir.
- Los Roles deben existir.
- Las relaciones Persona/Rol deben referenciar registros existentes.
- Las Etiquetas deben referenciar registros existentes.
- Las relaciones de continuidad deben referenciar números existentes.
- No deben existir relaciones Persona/Rol duplicadas conceptualmente.
- No deben existir relaciones de continuidad inconsistentes.
- No deben existir referencias a páginas inexistentes.
- El procesamiento no debe dejar una obra aparentemente disponible cuando el procesamiento haya fallado o no haya finalizado.
- La eliminación del contenido digital no debe eliminar el Número.

Las reglas de integridad deben reforzarse en Application y Persistence.

---

# 23. Seguridad

Todas las operaciones administrativas deben requerir:

- Usuario autenticado.
- Rol `Administrator`.

Los usuarios públicos no pueden:

- Crear Números.
- Modificar Números.
- Desactivar Números.
- Reactivar Números.
- Cargar CBR.
- Eliminar contenido digital.
- Modificar Personas/Roles asociados.
- Modificar Etiquetas asociadas.
- Solicitar operaciones administrativas de procesamiento.

Las imágenes y páginas procesadas son recursos privados y no deben exponerse mediante almacenamiento público directo.

---

# 24. Experiencia de administración

El formulario debe permitir trabajar progresivamente con la información del Número.

En particular:

- Crear Personas sin abandonar el formulario.
- Crear Roles sin abandonar el formulario.
- Seleccionar Personas existentes.
- Seleccionar Roles existentes.
- Agregar múltiples combinaciones Persona/Rol.
- Crear y seleccionar Etiquetas.
- Recibir sugerencias de Etiquetas mediante IA.
- Generar una descripción mediante IA.
- Editar la descripción generada.
- Cargar un CBR sin bloquear la edición.
- Consultar el estado del procesamiento.
- Reintentar un procesamiento fallido.

El formulario no debe perder los datos ingresados al abrir los modales de creación de Persona o Rol.

---

# 25. Fuera de alcance

Esta User Story no comprende:

- Administración manual de páginas.
- Edición individual de páginas.
- Ordenamiento manual de páginas.
- OCR.
- Lectura pública.
- Progreso de lectura.
- Historial de lectura.
- Favoritos.
- Valoraciones.
- Reseñas.
- Recomendaciones.
- Listas de lectura.
- Arcos.
- Crossovers.
- Listas personalizadas.
- Gestión de novelas gráficas.
- Cambio de Serie de un Número.
- Administración pública del catálogo.
- IA para usuarios públicos.

Las listas de tipo Arco, Crossover o Personal serán administradas mediante `US-0024 — Administrar listas de obras`.

26. Cargar un archivo CBR.
27. Consultar el estado de procesamiento.
28. Consultar errores de procesamiento.
29. Reintentar un procesamiento fallido.
30. Eliminar el contenido digital.
31. Continuar editando metadata mientras el contenido se procesa.
32. Desactivar o reactivar el Número sin afectar el procesamiento.
33. Mantener la integridad de todas las relaciones del catálogo.

Como resultado, cada Serie debe poder administrar sus Números como unidades independientes de publicación y lectura, manteniendo correctamente su metadata, continuidad, participantes, clasificación y contenido digital.

- [ ] El administrador puede acceder al listado de Números desde una Serie.

- [ ] El administrador puede buscar por Título.
- [ ] El administrador puede filtrar por estado activo.
- [ ] El administrador puede filtrar por Idioma.
- [ ] El administrador puede filtrar por fecha de publicación desde/hasta.
- [ ] El administrador puede filtrar por estado del contenido.
- [ ] El administrador puede ordenar por Número.
- [ ] El administrador puede ordenar por Título.
- [ ] El administrador puede ordenar por Fecha de publicación.
- [ ] El administrador puede ordenar por Fecha de subida.
- [ ] El administrador puede ordenar por Idioma.
- [ ] El listado muestra portada, estado activo, Número, Título, fechas, continuidad y estado de contenido.
- [ ] El administrador puede crear un Número.
- [ ] El administrador puede editar un Número.
- [ ] El administrador puede desactivar un Número.
- [ ] El administrador puede reactivar un Número.
- [ ] El Número pertenece obligatoriamente a una Serie.
- [ ] La Serie no puede modificarse desde el formulario del Número.
- [ ] La Editorial y la Franquicia se muestran como contexto informativo.
- [ ] `Number` es texto libre.
- [ ] `Number` es único dentro de la Serie.
- [ ] El título es obligatorio.
- [ ] El idioma es obligatorio.
- [ ] La fecha de publicación es obligatoria y no contiene hora.
- [ ] La fecha de subida es generada automáticamente por el sistema.
- [ ] El administrador puede establecer Número anterior.
- [ ] El administrador puede establecer Número siguiente.
- [ ] Las relaciones de continuidad se mantienen bidireccionalmente.
- [ ] El administrador puede asociar múltiples Personas y Roles.
- [ ] Una Persona puede tener múltiples Roles en el mismo Número.
- [ ] Un Rol puede tener múltiples Personas en el mismo Número.
- [ ] El administrador puede crear Personas desde el formulario.
- [ ] El administrador puede crear Roles desde el formulario.
- [ ] Las Personas y Roles creados quedan disponibles inmediatamente para selección.
- [ ] El administrador puede asociar múltiples Etiquetas.
- [ ] El administrador puede escribir nuevas Etiquetas.
- [ ] Las Etiquetas nuevas no generan duplicados.
- [ ] El administrador puede solicitar sugerencias de Etiquetas mediante IA.
- [ ] Las sugerencias de IA requieren confirmación del administrador.
- [ ] El administrador puede solicitar una descripción mediante IA.
- [ ] La descripción generada puede ser editada antes de guardar.
- [ ] El administrador puede cargar un archivo CBR.
- [ ] El procesamiento del CBR es asíncrono.
- [ ] El administrador puede continuar editando metadata durante el procesamiento.

- [ ] El contenido puede encontrarse en estado Finalizado OK.
- [ ] El contenido puede encontrarse en estado Error.
- [ ] Los errores muestran detalle.
- [ ] Los errores permiten solicitar un nuevo procesamiento.
- [ ] El contenido digital puede eliminarse.
- [ ] El CBR original no se conserva después del procesamiento.
- [ ] Las páginas se generan automáticamente y no se administran manualmente.
- [ ] `IsActive` es independiente del estado del contenido digital.
- [ ] Desactivar un Número no interrumpe un procesamiento en curso.
- [ ] Un Número puede permanecer activo sin contenido digital.
- [ ] Un Número sin contenido procesado no queda disponible para lectura pública.
