# US — Análisis de Work mediante IA en segundo plano

## Objetivo

Como administrador del catálogo,

quiero solicitar el análisis de una Work mediante IA sin tener que esperar la respuesta del proveedor,

para poder continuar cargando y procesando otras Works y posteriormente utilizar el resultado persistido por la IA para completar la información de cada obra.

## Descripción

Una Work puede ser cargada y procesada independientemente del análisis de IA.

El flujo de contenido existente continúa siendo:

```text
Work creada
    ↓
Content: Missing
    ↓
Hangfire comienza procesamiento
    ↓
Content: Processing
    ↓
Hangfire finaliza
    ↓
Content: Finished
```

Una vez que el contenido está `Finished`, el administrador puede seleccionar determinadas páginas y solicitar su análisis mediante IA.

La solicitud de IA no debe ejecutarse dentro del request HTTP ni obligar al administrador a esperar la respuesta del proveedor.

El flujo será:

```text
Content: Finished
    ↓
Administrador selecciona páginas
    ↓
Solicitar análisis IA
    ↓
IARequest = true
IAResponse = null
    ↓
Crear Job de Hangfire
    ↓
Administrador continúa trabajando
    ↓
Hangfire procesa la solicitud
    ↓
Éxito → IAResponse = JSON
Error → esperar 1–10 minutos → reintentar
```

## Estado de IA

La Work debe almacenar:

```text
IARequest   boolean
IAResponse  JSON nullable
```

Estos campos representan estados diferentes y no deben confundirse.

| IARequest | IAResponse | Significado                                |
| --------- | ---------- | ------------------------------------------ |
| false     | null       | Nunca se solicitó análisis IA              |
| true      | null       | Análisis solicitado, todavía pendiente     |
| true      | JSON       | Análisis solicitado y resultado disponible |

`IAResponse` representa una propuesta de información obtenida mediante IA.

La IA no modifica directamente los datos definitivos de la Work.

El administrador continúa siendo responsable de revisar el resultado y decidir qué información incorporar a la Work.

## Solicitud de análisis

Al solicitar un análisis:

1. La Work debe tener su contenido en estado `Finished`.
2. El administrador selecciona las imágenes que serán analizadas.
3. `IARequest` pasa a `true`.
4. `IAResponse` pasa a `null`.
5. Se crea un Job de Hangfire.
6. El request HTTP finaliza sin esperar al proveedor de IA.

La operación debe ser independiente del tiempo que tarde el proveedor de IA en responder.

## Worker de IA

El Job debe recibir:

* `WorkId`
* identificadores de las imágenes seleccionadas

No debe almacenar bytes de imágenes.

En cada intento, el Worker debe recuperar la Work y las imágenes necesarias y reconstruir la solicitud al proveedor de IA.

### Reintentos

Si el proveedor de IA:

* devuelve un error;
* no responde correctamente;
* devuelve una respuesta inválida;
* devuelve contenido que no puede ser convertido al contrato esperado;

el Job debe programar un nuevo intento.

El intervalo entre intentos debe ser un valor aleatorio entre **1 y 10 minutos**.

Los reintentos continúan hasta obtener una respuesta válida.

No se establece un número máximo de reintentos para esta funcionalidad.

## Resultado del análisis

Cuando el proveedor devuelve una respuesta válida:

1. El backend debe parsear y validar la respuesta.
2. Debe normalizarla al contrato de análisis de Work.
3. Debe serializar ese resultado como JSON.
4. Debe persistirlo en `IAResponse`.

El resultado almacenado debe ser el JSON normalizado correspondiente al contrato de análisis.

No debe almacenarse como `IAResponse` la respuesta textual/cruda del proveedor.

Una respuesta inválida no debe considerarse un análisis exitoso ni persistirse como resultado disponible.

## Reanálisis

Una Work que ya tenga `IAResponse` puede volver a analizarse.

Cuando el administrador solicita un nuevo análisis:

```text
IARequest = true
IAResponse = null
```

y se crea un nuevo Job.

El resultado anterior queda descartado.

Cuando el nuevo Job obtiene una respuesta válida, `IAResponse` se reemplaza por el nuevo JSON.

Esto permite volver a consultar la IA cuando el resultado anterior sea insuficiente, incorrecto o haya devuelto información vacía.

## Uso del resultado en el formulario

Cuando el administrador ingresa a editar una Work:

### Sin `IAResponse`

No deben mostrarse propuestas de IA.

El formulario funciona normalmente.

### Con `IAResponse`

El frontend obtiene el resultado almacenado desde el backend y muestra las propuestas de IA utilizando el mismo comportamiento visual utilizado actualmente para las sugerencias del análisis.

Las sugerencias de IA no reemplazan automáticamente los valores actuales de la Work.

El administrador puede aceptar, modificar o ignorar cada información propuesta antes de guardar la Work.

## Filtros de la grilla de Works

La grilla debe incorporar tres nuevos filtros.

### IARequest

Valores:

* Todos
* Sí
* No

Comportamiento:

* **Sí** → `IARequest = true`
* **No** → `IARequest = false`
* **Todos** → sin filtro

### IAResponse

Valores:

* Todos
* Sí
* No

Comportamiento:

* **Sí** → `IAResponse` contiene un resultado.
* **No** → `IAResponse` es `null`.
* **Todos** → sin filtro.

### WithDescription

Valores:

* Todos
* Sí
* No

Comportamiento:

* **Sí** → `Description` contiene información.
* **No** → `Description` está vacía o es `null`.
* **Todos** → sin filtro.

Los tres filtros deben poder combinarse entre sí y con los filtros existentes, incluido `Content Status`.

## Casos de uso de los filtros

### 1. Works procesadas que todavía no fueron enviadas a IA

```text
Content Status = Finished
IARequest = No
IAResponse = Todos
WithDescription = Todos
```

Permite encontrar las obras que ya están disponibles para análisis pero todavía nunca fueron enviadas a la IA.

### 2. Works con análisis disponible que todavía necesitan completar información

```text
Content Status = Finished
IARequest = Sí
IAResponse = Sí
WithDescription = No
```

Permite encontrar las obras que:

* ya terminaron de procesar su contenido;
* fueron enviadas a la IA;
* ya recibieron respuesta;
* todavía no tienen descripción.

Estas son obras listas para que el administrador entre y utilice la información propuesta por la IA.

### 3. Works con análisis disponible y descripción ya completada

```text
Content Status = Finished
IARequest = Sí
IAResponse = Sí
WithDescription = Sí
```

Permite identificar las obras que ya fueron analizadas por IA y que ya tienen descripción.

El administrador puede utilizar esta combinación para consultar las obras que ya pasaron por el flujo completo.

## Independencia entre Content e IA

El procesamiento del contenido y el procesamiento de IA son procesos independientes.

```text
Content
Missing → Processing → Finished

IA
Not requested → Requested → Response available
```

El estado de contenido no debe determinar automáticamente el estado de IA.

Una Work puede estar:

```text
Content = Processing
IARequest = false
```

o:

```text
Content = Finished
IARequest = true
IAResponse = null
```

o:

```text
Content = Finished
IARequest = true
IAResponse = JSON
```

El análisis IA solamente puede ser solicitado cuando el contenido necesario esté disponible.

## Criterios de aceptación

* [ ] La Work posee `IARequest`.
* [ ] La Work posee `IAResponse` como JSON nullable.
* [ ] `IARequest` comienza en `false`.
* [ ] `IAResponse` comienza en `null`.
* [ ] El análisis IA solamente puede solicitarse cuando el contenido está `Finished`.
* [ ] Solicitar análisis establece `IARequest = true`.
* [ ] Solicitar un nuevo análisis establece `IAResponse = null`.
* [ ] Solicitar análisis crea un Job de Hangfire.
* [ ] El request HTTP no espera la respuesta del proveedor.
* [ ] El Job almacena `WorkId` e identificadores de imágenes, no bytes.
* [ ] El Worker reconstruye la solicitud en cada intento.
* [ ] Los errores del proveedor generan nuevos intentos automáticos.
* [ ] Cada reintento espera un intervalo aleatorio entre 1 y 10 minutos.
* [ ] Los reintentos continúan hasta obtener una respuesta válida.
* [ ] Una respuesta inválida no se considera exitosa.
* [ ] Una respuesta válida se normaliza y persiste como JSON en `IAResponse`.
* [ ] El análisis no modifica automáticamente los datos definitivos de la Work.
* [ ] Una Work con `IAResponse` puede volver a analizarse.
* [ ] El formulario muestra las propuestas almacenadas cuando existe `IAResponse`.
* [ ] El formulario no muestra propuestas IA cuando `IAResponse` es `null`.
* [ ] Las propuestas IA requieren decisión del administrador antes de modificar la Work.
* [ ] La grilla permite filtrar por `IARequest`.
* [ ] La grilla permite filtrar por `IAResponse`.
* [ ] La grilla permite filtrar por `WithDescription`.
* [ ] Los tres filtros aceptan `Sí`, `No` y `Todos`.
* [ ] Los filtros pueden combinarse entre sí.
* [ ] Los filtros pueden combinarse con `Content Status`.
* [ ] `Content Status` e IA mantienen estados independientes.
