# US-0018 — Administrar novelas gráficas

## Tipo

User Story funcional.

## Épica

EPIC-02 — Gestión del catálogo y contenido editorial.

## Objetivo

Permitir que el administrador registre y mantenga novelas gráficas dentro del catálogo de Comic Library.

Una novela gráfica representa una obra individual e independiente.

Una novela gráfica posee las mismas características editoriales y de contenido que un número, pero no pertenece a una serie, no posee numeración editorial y no participa de relaciones de continuidad.

Por lo tanto, **Número y Novela Gráfica comparten el concepto de obra**, diferenciándose únicamente por las características específicas de un número.

---

## Concepto de obra

El catálogo debe considerar una abstracción común para las obras que pueden ser publicadas y leídas.

Conceptualmente:

```text
Work
├── Number
└── GraphicNovel
```

Una obra contiene las características comunes:

- Identidad.
- Título.
- Descripción.
- Editorial.
- Idioma.
- Fecha de publicación.
- Portada.
- Personas.
- Roles.
- Etiquetas.
- Contenido digital.
- Páginas.
- Estado de actividad.
- Estado de procesamiento.

Un **Número** agrega:

- Serie.
- Número editorial.
- Número anterior.
- Número siguiente.

Una **Novela Gráfica** no agrega estas características.

Por lo tanto:

```text
Number
    = Work + Series + Number + Continuity

GraphicNovel
    = Work
```

La implementación debe evitar duplicar en Novela Gráfica las responsabilidades que ya corresponden al concepto común de obra.

---

## Diferencia entre Número y Novela Gráfica

| Característica | Número | Novela gráfica |
|---|---:|---:|
| Título | Sí | Sí |
| Descripción | Sí | Sí |
| Editorial | Sí | Sí |
| Idioma | Sí | Sí |
| Fecha de publicación | Sí | Sí |
| Portada | Sí | Sí |
| Personas | Sí | Sí |
| Roles | Sí | Sí |
| Etiquetas | Sí | Sí |
| Contenido digital | Sí | Sí |
| Páginas | Sí | Sí |
| Estado | Sí | Sí |
| Serie | Sí | **No** |
| Número editorial | Sí | **No** |
| Número anterior | Sí | **No** |
| Número siguiente | Sí | **No** |

Una novela gráfica **no debe ser modelada como un número perteneciente a una serie ficticia** para reutilizar funcionalidades.

Tampoco debe incorporar propiedades de continuidad únicamente para compartir implementación.

---

## Actor

Administrador.

Las operaciones administrativas requieren:

- Usuario autenticado.
- Rol `Administrator`.

---

## Alcance

El administrador debe poder:

- Consultar novelas gráficas.
- Crear novelas gráficas.
- Consultar el detalle.
- Modificar novelas gráficas.
- Activarlas y desactivarlas.
- Asociar editorial.
- Asociar idioma.
- Asociar personas y roles.
- Asociar etiquetas.
- Asociar portada.
- Incorporar contenido digital.
- Consultar el estado del contenido digital.

Las funcionalidades comunes con Número deben reutilizar el concepto y las capacidades comunes de `Work`.

---

## Información de la novela gráfica

Una novela gráfica debe disponer, como mínimo, de:

- Identificador.
- Título.
- Descripción.
- Editorial.
- Idioma.
- Fecha de publicación.
- Portada.
- Personas y roles.
- Etiquetas.
- Estado de actividad.
- Estado del contenido digital.

No debe contener:

- Serie.
- Número editorial.
- Número anterior.
- Número siguiente.

---

## Editorial

Una novela gráfica puede asociarse con una Editorial existente.

La información de la editorial no debe duplicarse.

La relación debe utilizar la referencia al registro existente.

La desactivación de la editorial no debe eliminar ni desactivar automáticamente la novela gráfica.

---

## Idioma

Una novela gráfica puede asociarse con un Idioma existente.

El idioma debe referenciar una entidad existente.

La desactivación de un idioma no debe romper las relaciones existentes.

---

## Personas y roles

Una novela gráfica puede tener múltiples participantes.

Cada participación debe especificar un rol.

Una misma persona puede desempeñar múltiples roles.

Por ejemplo:

```text
Persona A → Guionista
Persona A → Dibujante
Persona B → Colorista
```

No debe existir más de una relación idéntica:

```text
Novela gráfica + Persona + Rol
```

Deben reutilizarse las reglas establecidas para las relaciones entre obras, personas y roles.

---

## Etiquetas

Una novela gráfica puede tener múltiples etiquetas.

Una etiqueta puede pertenecer a múltiples obras.

No deben existir asociaciones duplicadas.

La desactivación de una etiqueta no debe eliminar la novela gráfica.

La gestión de las etiquetas debe reutilizar el mecanismo establecido para los números.

---

## Portada

Una novela gráfica puede tener una portada.

La portada debe ser un recurso administrado por la aplicación y perteneciente a la obra correspondiente.

Las imágenes del catálogo son privadas.

La selección o modificación de la portada debe reutilizar el mecanismo común de gestión de portadas de las obras.

---

## Contenido digital

Una novela gráfica puede disponer de contenido digital procesado.

Debe utilizar el mismo mecanismo de importación y procesamiento definido para las demás obras del catálogo.

La implementación de esta User Story **no debe duplicar el procesamiento CBR/CBZ**.

El contenido debe procesarse mediante el mecanismo definido en:

**US-0026 — Importar y procesar obras digitales.**

El estado del contenido digital debe ser independiente del estado de actividad de la novela gráfica.

Por ejemplo:

```text
IsActive = true
ContentStatus = Processing
```

indica que la obra está activa pero todavía no disponible para lectura.

---

## Páginas

Las páginas pertenecen a la obra.

Cada página debe poder identificarse inequívocamente mediante:

- Identificador.
- Obra.
- Orden.
- Referencia al recurso almacenado.

Las páginas deben poder solicitarse individualmente.

La administración manual de páginas no forma parte de esta User Story.

La infraestructura utilizada para las páginas debe ser común a las obras del catálogo.

---

## Continuidad

Las novelas gráficas **no participan de la continuidad de números** definida por US-0025.

No deben tener:

- Número anterior.
- Número siguiente.

No debe ser necesario crear relaciones de continuidad para una novela gráfica.

Una eventual relación narrativa de una novela gráfica con otras obras deberá resolverse mediante mecanismos específicamente definidos por otra funcionalidad y no mediante la continuidad de números.

---

## Series

Una novela gráfica no pertenece a una Serie.

No debe ser necesario crear una Serie para registrar una novela gráfica.

El sistema debe impedir que una novela gráfica sea asociada a una Serie mediante las operaciones propias de esta entidad.

---

## Numeración

Una novela gráfica no posee número editorial.

No debe utilizarse un campo `Number` para representar artificialmente su identidad editorial.

Su identidad se basa en su propio identificador y título, junto con las demás propiedades definidas para la obra.

---

## Estado de actividad

La novela gráfica debe poder desactivarse lógicamente.

La desactivación no debe eliminar:

- La obra.
- Sus relaciones.
- Sus imágenes.
- Sus páginas.
- Su portada.
- Sus participantes.
- Sus etiquetas.

Debe poder reactivarse posteriormente.

El estado de actividad es independiente del estado del contenido digital.

---

## Listado administrativo

El administrador debe poder consultar las novelas gráficas desde el Dashboard.

El listado debe soportar, cuando corresponda:

- Búsqueda.
- Filtrado.
- Ordenamiento.
- Paginación.

Debe poder identificarse como mínimo:

- Título.
- Editorial.
- Idioma.
- Fecha de publicación.
- Estado.
- Estado del contenido.

No debe confundirse una novela gráfica con un número durante la consulta.

---

## Detalle administrativo

El administrador debe poder consultar el detalle de una novela gráfica.

El detalle debe mostrar la información común de la obra:

- Información editorial.
- Editorial.
- Idioma.
- Fecha de publicación.
- Personas.
- Roles.
- Etiquetas.
- Portada.
- Estado.
- Estado del contenido.
- Información del contenido digital.

No debe mostrar información propia de números:

- Serie.
- Número editorial.
- Número anterior.
- Número siguiente.

---

## Creación

El administrador debe poder crear una novela gráfica proporcionando los datos requeridos.

Durante la creación:

- Las referencias deben validarse.
- La Editorial debe existir cuando sea requerida.
- El Idioma debe existir cuando sea requerido.
- Las Personas deben existir.
- Los Roles deben existir.
- Las Etiquetas deben seguir el mecanismo establecido para las obras.
- No deben generarse relaciones de Serie.
- No deben generarse relaciones de continuidad.
- No debe requerirse un número editorial.

La creación debe reutilizar las capacidades comunes de las obras en lugar de duplicarlas.

---

## Modificación

El administrador debe poder modificar una novela gráfica existente.

Debe poder actualizar:

- Título.
- Descripción.
- Editorial.
- Idioma.
- Fecha de publicación.
- Personas y roles.
- Etiquetas.
- Portada.

La modificación no debe cambiar el identificador de la obra.

No debe permitir agregar:

- Serie.
- Número editorial.
- Número anterior.
- Número siguiente.

---

## Integridad

El sistema debe impedir:

- Referencias a editoriales inexistentes.
- Referencias a idiomas inexistentes.
- Referencias a personas inexistentes.
- Referencias a roles inexistentes.
- Referencias a etiquetas inexistentes.
- Relaciones duplicadas.
- Recursos pertenecientes a otra obra utilizados como portada.
- Páginas pertenecientes a otra obra.
- Relaciones de continuidad propias de números.

Una novela gráfica no debe poder quedar relacionada con una Serie o con la continuidad de números.

Las reglas deben reforzarse mediante Application y Persistence.

---

## Seguridad

Todas las operaciones administrativas requieren:

- Usuario autenticado.
- Rol `Administrator`.

La autorización debe realizarse en backend.

El Dashboard no constituye el mecanismo de seguridad.

Los contratos de entrada no deben permitir modificar identificadores que provienen de la ruta o del contexto de la operación.

---

## Reutilización

La implementación de esta User Story debe **priorizar la reutilización de las capacidades comunes existentes en US-0017**.

No deben duplicarse innecesariamente:

- Gestión de imágenes.
- Portadas.
- Páginas.
- Contenido digital.
- Personas y roles.
- Etiquetas.
- Estados.
- Validaciones comunes.
- Procesamiento de obras.
- Reglas de seguridad.

Las diferencias entre Número y Novela Gráfica deben limitarse a las propiedades y reglas que realmente sean específicas de cada tipo.

La introducción de esta User Story puede requerir refactorizar las capacidades actualmente implementadas para Número hacia el concepto común de `Work`, siempre que sea necesario para evitar duplicación.

**No debe duplicarse código simplemente para evitar modificar la implementación existente de Número.**

---

## Fuera de alcance

No comprende:

- Exploración pública.
- Búsqueda pública.
- Lector.
- Progreso de lectura.
- Historial.
- Favoritos.
- Valoraciones.
- Reseñas.
- Recomendaciones.
- Listas de usuarios.
- Listas comunitarias.
- OCR.
- Búsqueda semántica.
- IA orientada al usuario.
- Continuidad entre números.
- Gestión de Series.
- Procesamiento CBR como funcionalidad independiente.

## Criterios de aceptación

### CA-01 — Consultar novelas gráficas

El administrador puede consultar el listado de novelas gráficas.

### CA-02 — Consultar detalle

El administrador puede consultar el detalle de una novela gráfica.

### CA-03 — Crear novela gráfica

El administrador puede crear una novela gráfica sin proporcionar Serie ni número editorial.

### CA-04 — Modificar novela gráfica

El administrador puede modificar la información de una novela gráfica existente.

### CA-05 — Desactivar

El administrador puede desactivar una novela gráfica sin eliminar físicamente sus datos.

### CA-06 — Reactivar

El administrador puede reactivar una novela gráfica desactivada.

### CA-07 — Editorial e idioma

El sistema permite asociar una Editorial y un Idioma existentes.

### CA-08 — Personas y roles

El sistema permite asociar múltiples personas y roles, incluyendo múltiples roles para una misma persona.

### CA-09 — Etiquetas

El sistema permite asociar múltiples etiquetas sin duplicar relaciones.

### CA-10 — Portada

El administrador puede seleccionar una portada perteneciente a la novela gráfica.

### CA-11 — Contenido digital

La novela gráfica puede utilizar el mecanismo común de importación y procesamiento de contenido digital.

### CA-12 — Páginas

Las páginas generadas pertenecen inequívocamente a la novela gráfica y pueden recuperarse individualmente.

### CA-13 — Sin Serie

Una novela gráfica no puede pertenecer a una Serie.

### CA-14 — Sin numeración

Una novela gráfica no posee número editorial.

### CA-15 — Sin continuidad

Una novela gráfica no puede participar de las relaciones de número anterior/número siguiente.

### CA-16 — Reutilización

Las capacidades comunes con Número deben reutilizarse mediante el concepto común de obra, evitando duplicación innecesaria de lógica y persistencia.

### CA-17 — Integridad

No pueden existir referencias a entidades inexistentes ni relaciones duplicadas o huérfanas.

### CA-18 — Seguridad

Todas las operaciones administrativas requieren autenticación y rol `Administrator`.

---

## Resultado esperado

Al finalizar **US-0018**, Comic Library debe poder administrar novelas gráficas como **obras independientes**, reutilizando las capacidades comunes de los números y diferenciándolas únicamente por las características que les son propias.

Conceptualmente:

```text
                    WORK
                     │
          ┌──────────┴──────────┐
          │                     │
       NUMBER              GRAPHIC NOVEL
          │
     ┌────┼─────┐
     │    │     │
  SERIES  #   CONTINUITY
```

La regla fundamental de esta User Story es:

> **No debemos implementar una segunda "versión de Number". Debemos reutilizar el concepto común de Work y agregar a Number únicamente aquello que lo diferencia de una novela gráfica.**
