| Button | `components/ui/button.tsx` | Base button with shadcn/ui variants |
| Dialog | `components/ui/dialog.tsx` | Modal dialog on top of Radix Dialog. The visual language is the `neps` palette. Parts: `Dialog`, `DialogContent`, `DialogHeader`, `DialogTitle`, `DialogDescription`, `DialogFooter`, `DialogClose`, `DialogTrigger`. |
| ConfirmDialog | `components/ui/confirm-dialog.tsx` | Confirmation before an operation that cannot be undone. The destructive action is the one the dialog asks for, so the cancel button comes first and the confirmation carries the accent color. |

| PasswordInput | `features/authentication/components/password-input.tsx` | Password input with visibility toggle, optional hint, and visual validation rules |
| OtpInputs | `features/authentication/components/otp-inputs.tsx` | Shared 6-digit numeric inputs for OTP codes with navigation, Backspace, and paste support |
| NumbersPage | `pages/numbers-page.tsx` | Number listing page (global and per-Series) with TanStack Query, search, filters (active, language, content status, publication date range), sort (number, title, publication date, upload date, language), pagination, contextual header, confirmation modals, deactivate/reactivate/retry actions. Protected by `ProtectedRoute`. |
| NumberFormPage | `pages/number-form-page.tsx` | Number creation and editing page with React Hook Form + Zod, series context (immutable), CBR/CBZ upload, processed images gallery with cover selection, multi-image selection for AI analysis, AI result editable, separated recommended tags/characters with accept/dismiss, person+role pairs with in-page create modals, tag input, AI suggestions, continuity, content retry/delete (when applicable), confirmation modal, and success toast. Protected by `ProtectedRoute`. |

| LanguageSearchSelect | `features/numbers/components/language-search-select.tsx` | Searchable select for language selection. Loads all languages once and filters client-side, with keyboard navigation and clear button. |
| NumberSearchSelect | `features/numbers/components/number-search-select.tsx` | Searchable select for number selection filtered by series, with debounced search, keyboard navigation, and clear button. Used to set previous/next continuity. |
| TagInput | `features/numbers/components/tag-input.tsx` | Tag input with chip display, Enter to add, Backspace to remove last, comma-separated paste support, and configurable max tags. |
| CountrySearchSelect | `features/authentication/components/country-search-select.tsx` | Searchable combo for country/nationality selection with progressive page loading |
| UserMenu | `features/authentication/components/user-menu.tsx` | Dropdown user menu with avatar, name, email, and navigation options (Edit Profile, My Library, Settings, Logout) |
| ProtectedImage | `components/protected-image.tsx` | Reusable component for displaying protected backend images (`/images/{id}`) via Blob and Object URL. External HTTP/HTTPS URLs and data URLs displayed directly |
| DashboardHeader | `components/dashboard/dashboard-header.tsx` | Dashboard header with main navigation, search, and user menu |
| DashboardWelcome | `components/dashboard/dashboard-welcome.tsx` | Dashboard welcome card with personalized greeting, reading stats, and catalog exploration action |
| ContinueReadingSection | `components/dashboard/continue-reading-section.tsx` | "Continue Reading" section of the index: heading, the `Ver historial` link to Mi colección, and the grid of works the user is reading, most recent activity first. Loading and error are shown in place; **without works in reading the whole section disappears**, so it never reserves space on the index. |
| ContinueReadingCard | `components/dashboard/continue-reading-card.tsx` | One work in progress: cover on the left, publisher, title, progress bar, percentage and current/total page on the right. Horizontal composition, deliberately different from `WorkCard` (a cover grid). Cover through `ProtectedImage`, publisher color through `readableAccentColor`, progress taken from the API with the shared reading scale, and the whole card resumes reading at `/works/{id}/read`. |
| useContinueReading | `features/catalog/hooks/use-continue-reading.ts` | Works the user is reading for that section: reading history filtered to `Reading` and capped to 12, most recent activity first. |
| CatalogSection | `components/dashboard/catalog-section.tsx` | Recommended works section of the index: heading, ordering selector, cover grid and the loading/error states. With no eligible works it renders nothing, so it reserves no space on the index. |
| RecommendedWorkCard | `features/catalog/components/recommended-work-card.tsx` | One recommended work: 2:3 cover with `object-cover` and a `★ X.X` badge when the work has ratings, plus publisher, title and available editorial data (number and publication year) below. Different composition from `WorkCard` on purpose: pure discovery, no hierarchy pills, no work type, no reading scale. The average comes from `averageRating` in the listing contract. Like `WorkCard`, the card opens the work detail through a link that covers it, so the favorite star and the personal lists button next to the title are buttons of their own. |
| RecommendedSortControls | `features/catalog/components/recommended-sort-controls.tsx` | Ordering selector (`Más populares`, `Agregados recientemente`, `Más votados`). Each option is the `sortBy` value the backend expects. |
| useRecommendedWorks | `features/catalog/hooks/use-recommended-works.ts` | `useQuery` over `GET /api/works/recommended` with the selected criterion in the key. `staleTime: 0`: the eligible set changes as soon as the user starts reading a work. |
| DashboardFooter | `components/dashboard/dashboard-footer.tsx` | Dashboard footer with copyright and support/terms links |
| WorksPage | `features/catalog/components/works-page.tsx` | Shared catalog exploration page for `/catalog`, `/publishers/:id`, `/franchises/:id`, `/series/:id` and `/favorites`. Includes search, structural filters, WorkType filter, cascade autocomplete, sorting, infinite scroll, URL state, and contextual headers. `HIDDEN_PILLS_BY_CONTEXT` maps each route to the levels its WorkCards should not repeat. The `favorites` context is the catalog with the single extra criterion `isFavorite=true` in the query and in the cache namespace, so there is no second catalog. Optional `header`, `emptyMessage` and `resultLabel` let the page name itself and describe its own empty state. |
| WorkCard | `features/catalog/components/work-card.tsx` | Reusable work card for catalog results. Hierarchy pills (Publisher/Franchise/Series) sit at the top of the cover and the WorkType pill at the bottom right. Pills do not navigate: they emit the work's resolved hierarchy through `onSelectEntity` and the page turns it into URL filters. `hiddenPills` drops the levels the current route already fixes, so a contextual page does not repeat itself on every card. The WorkType pill takes the color of the deepest level available: Series, else Franchise, else Publisher. The card opens the work detail through a link that covers it, with the content above it, so the favorite star and the personal lists button are never inside the link: clicking them never navigates and the keyboard reaches them as buttons. |
| FavoriteButton | `features/catalog/components/favorite-button.tsx` | The star that marks a work as a favorite of the authenticated user. It is the same control in every listing that shows works (`WorkCard` and `RecommendedWorkCard`), so the state of a work is the same everywhere it appears. The state comes from the `isFavorite` the backend returned with the work, and it only changes after the operation succeeds: a failed request leaves the previous state and shows the error. Favorite: amber star over an amber background. Not favorite: no background, muted star. `aria-pressed`, an accessible name with the title of the work, visible focus and disabled while the operation of that work is in flight. |
| PersonalListButton | `features/catalog/components/personal-list-button.tsx` | The button that opens the personal lists of a work. Blue when the work belongs to at least one personal list and gray when it does not; it never belongs to a single list, because a work can be in several at the same time. It is the same control in every listing that shows works (`WorkCard` and `RecommendedWorkCard`). |
| PersonalListsModal | `features/catalog/components/personal-lists-modal.tsx` | The personal lists of the user and the membership of a work: a search by name, the button to create a list, one row per list with the checkbox of the membership and the actions to rename or delete it, and the position indicator ("Mostrando 5 de 20") with the button to show the next ones. The lists come from `GET /api/users/me/lists` with the membership of the work, and the order of the response is kept: the lists that contain the work first and the rest after them. |
| PersonalListRow | `features/catalog/components/personal-list-row.tsx` | One list of the selector: the checkbox of the membership of the work, the name of the list, and the actions to rename and to delete it. |
| PersonalListNameDialog | `features/catalog/components/personal-list-name-dialog.tsx` | The dialog that asks for the name of a personal list, both to create one and to rename one. It validates that the name is not empty and shows the error the API returns. |
| SortableListWorkRow | `features/catalog/components/sortable-list-work-row.tsx` | A work of a personal list with the controls that order it: the handle that drags the row, and the buttons that move it one place up or down, which are the alternative that works with a finger and with the keyboard. |
| ListsPage | `features/catalog/pages/lists-page.tsx` | The exploration of the lists. The same page serves `/lists` (the lists of the system) and `/my-lists` (the personal lists of the user): the `myLists` prop is the only difference, and it becomes the criterion of the query. Search, hierarchy filters, infinite scroll of cards and the loading/error/empty states are shared. A personal list has no type of list, so that filter is not offered in the personal mode, and the card of a personal list shows no type pill. The pages are asked one at a time and kept in the state of the screen, without a cache between screens. |
| ListCard | `features/catalog/components/list-card.tsx` | One list of the exploration: vertical cover, accent bar, name, work count, reading progress and rating. The whole card is a link to the detail, and the type pill is only rendered when the list has a type, which a personal list does not. |
| ListWorkRow | `features/catalog/components/list-work-row.tsx` | One work of a list, as a row: order number, cover, title, publisher/number, individual reading progress and the reading action that opens the reader at `/lists/{listId}/work/{workId}`. The controls of the personal lists —the reordering and the removal of the work— are optional, so the same row serves the lists of the system. |
| EntityPill | `features/catalog/components/work-card.tsx` | Internal button for the Publisher/Franchise/Series hierarchy. Text and border keep the entity color; the background is black or white so the contrast does not depend on the cover artwork. Knows nothing about routes or URLs. |
| entityColor | `features/catalog/utils/entity-color.ts` | Color helpers shared by entity pills and the Publisher header: hex parsing, the luminance rule that picks the pill background (`readableBackgroundColor`), alpha composition for borders (`colorWithAlpha`), and `readableAccentColor`, which lightens an entity color only as far as needed for it to read as accent text on a given surface. All of them accept a missing color and fall back to neutrals. |
| optionMappers | `features/catalog/components/option-mappers.ts` | Maps filter DTOs to autocomplete options, carrying the parent ids and names the cascade needs (`publisherId` on a Franchise, `franchiseId` and `publisherId` on a Series). Detail lines are omitted when the backend returns null. |
| useCatalogUrlState | `features/catalog/hooks/use-catalog-url-state.ts` | Single owner of the catalog URL state. Reads and writes `search`, `idPublisher`, `idFranchise`, `idSerie`, `workTypeId`, `sort` and `direction`. Backend param names are translated here, so a URL rename does not touch the repositories. |
| CatalogSearch | `features/catalog/components/catalog-search.tsx` | General search input for Title, Summary, Number, Tags, and Person. Keeps the typed text in local state so it renders on every keystroke, and commits it to the URL only after 350ms of inactivity. |
| useDebouncedCallback | `features/catalog/hooks/use-debounced-callback.ts` | Returns `schedule` and `cancel` for a callback that runs only after the caller has been idle for a given delay. Used by the general search and by the entity autocompletes so the debounce logic is not duplicated. |
| SortControls | `features/catalog/components/sort-controls.tsx` | Sort field selector and direction toggle for catalog results. |
| EntityAutocomplete | `features/catalog/components/entity-autocomplete.tsx` | Reusable autocomplete for Publisher, Franchise, Series, and WorkType filters. Shows the entity name plus up to two detail lines (Franchise and Publisher) in smaller type. Keeps the typed text and the focus while typing (`inputValue`), shows the selected entity name when the input is empty (`selectedName`), and only clears the filter from the explicit clear action. |
| CatalogOptionMappers | `features/catalog/components/option-mappers.ts` | Pure mappers from filter DTOs to autocomplete options (`publisherOption`, `franchiseOption`, `seriesOption`, `workTypeOption`), including the parent ids needed by the cascade. |
| AppLayout | `app.tsx` | Global layout for protected routes only (`/index`, `/profile`, `/settings`, `/catalog`, `/publishers/:id`, `/franchises/:id`, `/series/:id`). Single sticky `DashboardHeader`, `Outlet` for the page, `DashboardFooter`. Must not use `overflow` on the scroll container, otherwise the sticky header stops working. Public/auth routes must not be nested in it; they use their own full-screen layout. |
| ResultsGrid | `features/catalog/components/results-grid.tsx` | Grid container for catalog results with loading, error, and empty states. Forwards `hiddenPills` to each `WorkCard`. |
| ContextualHeader | `features/catalog/components/contextual-header.tsx` | Contextual header for the Series page with entity initial and metadata. Superseded for Publisher and Franchise by `EntityHeader`. |
| EntityHeader | `features/catalog/components/entity-header.tsx` | Shared presentation for the contextual catalog headers. Takes the label (`Editorial`, `Franquicia`, `Serie`), name, color, image, description and optional facts/parent/website/history, plus the loading and error state. The logo fills its rounded box with no padding (`object-cover` on an `overflow-hidden` container) and keeps the `rounded-2xl` border in the entity color, falling back to a centered entity initial. The optional `parent` renders a second clickable pill for the level above, in that level's own color; selecting it writes the level into the URL without leaving the route. Every optional field is dropped when absent, including the separator between facts. The glow, gradient and outlines derive from the entity color; accent text goes through `readableAccentColor` so a dark color stays legible on the card. The message in the error state comes from the API, so the server owns its own wording. |
| PublisherHeader | `features/catalog/components/publisher-header.tsx` | Header of `/publishers/:id`. Binds `usePublisherDetail` to `EntityHeader` with the country and founded year as facts, the website and the history. |
| FranchiseHeader | `features/catalog/components/franchise-header.tsx` | Header of `/franchises/:id`. Binds `useFranchiseDetail` to `EntityHeader`, and turns the publisher that the detail carries into the secondary `Editorial` pill. |
| useEntityDetail | `features/catalog/hooks/use-entity-detail.ts` | Shared loader for the public entity detail endpoints. A 404 is a valid answer for an id that does not resolve, not a transport failure, so it is not retried and is reported apart from a real error. |
| usePublisherDetail | `features/catalog/hooks/use-publisher-detail.ts` | Publisher detail for the header and the publisher filter, sharing one cache entry. |
| useFranchiseDetail | `features/catalog/hooks/use-franchise-detail.ts` | Franchise detail for the header and the franchise filter, sharing one cache entry. |
| useToggleFavorite | `features/catalog/hooks/use-favorite.ts` | Adds or removes the favorite of a work (`POST` / `DELETE /api/favorites/{workId}`, through the shared API client and the authenticated user of the token). The state changes only after the operation succeeds. On success it propagates the new state to every cached listing: the favorites listing drops the work when it is removed, so its card leaves the results without a new request, and the catalog, the reading history and the recommended works reflect the new state of the work. The pending state is counted over every mutation of the work, so the same work on screen twice never runs two operations at once. |
| query keys | `features/catalog/hooks/query-keys.ts` | Cache namespaces of the listings that expose works: `works`, `favorites`, `reading-history` and `recommended-works`. The favorites listing has its own namespace because it is the catalog with the `isFavorite` criterion and holds a different set of works. It also holds the namespaces of the lists (`catalog-lists`, `personal-lists`) and the key of the detail of a list. |
| useWorksPagination | `features/catalog/hooks/use-works-pagination.ts` | First page plus infinite scroll of a works listing, shared by the catalog, the favorites and the reading history. The accumulated works are read from the cache of every loaded page, so a listing reflects the cached state of its works as soon as it changes without losing the pages already loaded. |
| useWorksListingCache | `features/catalog/hooks/work-listing-cache.ts` | The cached state of the works of the listings. Every listing that shows works shares the same cache, so the state of a work — whether it is a favorite, whether it belongs to a personal list — is updated in all of them at once, and a card never shows a state that another screen already changed. It can also remove a work from a listing or ask the backend for the state again. |
| usePersonalLists | `features/catalog/hooks/use-personal-lists.ts` | The personal lists of the user with the membership of a work, and the operations over them: add or remove a work from a list, and create, rename or delete a list. The lists are asked for every time the selector opens and every time the search changes, with no cache in between: what the selector shows is the last answer of the backend. The membership of the work is also written to the state of the listings that show works, so the button of the card follows the operation. The order of the lists is the one the endpoint returns. |
| useIsPersonalList | `features/catalog/hooks/use-personal-list-editing.ts` | Whether a list is a personal list of the authenticated user. The personal lists are the ones the user administers, so the detail of a list can only be edited when it belongs to the user. The endpoint of the personal lists answers 404 for a list of the system, which is the same answer as a list of another user. |
| usePersonalListWorks | `features/catalog/hooks/use-personal-list-editing.ts` | The operations over the works of a personal list: the new order (`PUT /api/users/me/lists/{listId}/works/order`, with only the works that change their place) and the removal of a work. Both only change the relation between the work and the list: the work keeps its progress, its ratings, its comments and its favorites. |
| useRemoteData | `features/catalog/hooks/use-remote-data.ts` | Loads a value from the API when the screen opens and whenever its dependencies change, and asks again when the screen needs it. The value is not cached: what the screen shows is always the last answer of the backend, so a change made from another screen is never hidden behind a state that is still "fresh". The lists use it; the listings of works keep the query cache. |
